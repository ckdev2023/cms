# 【客户中心】流程测试用例

> **备注【客户中心】**：本文件为客户中心（客户列表、客户详情、新建/编辑客户、家属随附、主案件列表摘要等）的**手工 / UAT 流程测试**用例集。

## 1. 主流程 MTP（初回 → 入档）

**目标**：验证「第一次来访 → 确定在本所办理 → 完成最小入档」在客户中心可闭环。

| 步骤 ID | 操作 | 预期结果 | 通过 |
|---------|------|----------|------|
| MTP-01 | 登录后进入**客户列表**（客户中心总览） | 列表加载无报错，分页/筛选可用 | ☐ |
| MTP-02 | 使用姓名或电话**检索**不存在的客户 | 无重复则进入新建路径清晰 | ☐ |
| MTP-03 | **新建个人客户**，仅填写当前面谈可确定的必填项并保存 | 保存成功；列表可见新行 | ☐ |
| MTP-04 | 打开该客户**详情**，新增一条**备注**（初回相談・受任前/已受任等） | 备注保存成功且时间序正确 | ☐ |
| MTP-05 | 在详情或关联入口**创建签证案件**（或事务所规定的案件入口） | 案件与客户关联正确，类型/担当可辨 | ☐ |
| MTP-06 | 上传至少 1 个**文件**并绑定客户或案件 | 文件可在详情或文件模块追溯 | ☐ |
| MTP-07 | 将案件推进至下一**状态**（若适用） | 列表/详情状态一致 | ☐ |
| MTP-08 | 返回客户列表，确认该行**主展示案件摘要**（案件类型/状态等）与详情一致 | 与 `docs/17` §1.11 主展示规则观感一致；无空白异常 | ☐ |

## 2. 不同业务场景测试用例（Scenario Case）【客户中心】

> 下列为**端到端故事线**：每条可独立执行；与 §1 主流程重叠处可只测差异点。编号 **SC-xx** 便于缺陷单引用。

### SC-A — 标准个人单申（基准路径）

| 项 | 内容 |
|----|------|
| 背景 | 本人单独申请在留更新等，无家属同行建档需求 |
| 数据准备 | 无同名冲突的新电话 |
| 操作步骤 | ① 客户列表新建个人客户 → ② 详情写初回备注 → ③ 建 1 件签证案件 → ④ 上传 1 份资料 → ⑤ 列表确认主案件摘要 |
| 预期 | 全程无跳转错误；列表摘要与详情为同一主展示案件；无多余必填阻断当场入档 |
| 通过 | ☐ |

### SC-B — 家族同申（主申 + 随附家属）

| 项 | 内容 |
|----|------|
| 背景 | 活件挂在主申客户；家属为独立客户但业务上同属一案 |
| 数据准备 | 主客户已建；签证案件 `customer_id` 为主申 |
| 操作步骤 | ① 主客户表单添加 2 名随附家属并保存 → ② 列表分别打开主申行与家属行 → ③ 核对主案件摘要与回退标识（若已上线）→ ④ 家属详情确认 `primary` 关联正确 |
| 预期 | 家属行能看见主申侧主展示摘要时，不误判为家属本人 `customer_id` 案件；回退标签与权限一致（参见 §6） |
| 通过 | ☐ |

### SC-C — 法人客户 + 个人对接人（若产品支持法人主档）

| 项 | 内容 |
|----|------|
| 背景 | 认定等以会社为申请人，实际联络为特定个人 |
| 数据准备 | 法人客户类型可用 |
| 操作步骤 | ① 新建法人客户（或规则允许下的主档）→ ② 备注中写明对接人姓名与职务 → ③ 建案时核对「申请人」字段与备注一致 → ④ 列表/详情切换无歧义 |
| 预期 | 不会出现「对接人个人客户」与「申请主体」混用且无备注留痕 |
| 通过 | ☐ |

### SC-D — 书类不齐・仅相談未受任

| 项 | 内容 |
|----|------|
| 背景 | 客户未带齐资料，尚未正式受任 |
| 数据准备 | 可仅建客户不写案件 |
| 操作步骤 | ① 新建客户 → ② 备注标明「書類不足・未受任」→ ③ 尝试进入建案（可选）→ ④ 列表筛选「无案件」类条件（若有） |
| 预期 | 系统允许**最小主档**；状态/备注能区分「潜在客户」与「已受任活件」 |
| 通过 | ☐ |

### SC-E — 短窗口期限（高优先级跟进）

| 项 | 内容 |
|----|------|
| 背景 | 在留或法定期限临近，需依赖列表/Dashboard 提醒 |
| 数据准备 | 测试环境可设置临近到期的在留期限或案件日期 |
| 操作步骤 | ① 客户/案件带临近到期字段 → ② 客户列表 + Dashboard（若使用）查看是否命中提醒 → ③ 改期后提醒随之变化 |
| 预期 | 不因主展示案件选取规则漏显高风险行；日期修改后展示一致 |
| 通过 | ☐ |

### SC-F — 电话咨询后来所（防重复主档）

| 项 | 内容 |
|----|------|
| 背景 | 上周电话已登记，本周来所补全 |
| 数据准备 | 第一次已建客户同一电话 |
| 操作步骤 | ① 列表/检索用电话找到已有客户 → ② **不**再建新客户，打开编辑补全 → ③ 若误操作二次新建，观察是否有检索/合并提示 |
| 预期 | 优先检索续档；重复建档有培训口径内的提示或可追溯纠正 |
| 通过 | ☐ |

### SC-G — 他组担当客户（数据范围外）

| 项 | 内容 |
|----|------|
| 背景 | A 担当建案，B 担当同所不同组或无权限 |
| 数据准备 | 两个账号、一条他人客户 |
| 操作步骤 | ① A 登录确认可见 → ② B 登录检索同一姓名/ID → ③ B 打开直链（若可构造） |
| 预期 | B 不可见或行为符合 `dataScope` 设计；列表不出现越权摘要 |
| 通过 | ☐ |

### SC-H — 行政案件与签证并存（若双线启用）

| 项 | 内容 |
|----|------|
| 背景 | 同一客户既有签证又有行政书士案件 |
| 数据准备 | 同一 `customer_id` 下两类案件各 1 |
| 操作步骤 | ① 客户详情切换签证 Tab 与行政案件 Tab → ② 列表主摘要仍以 §1.11 规则为准 → ③ 文件分别绑定正确实体 |
| 预期 | Tab 数据不串档；主摘要规则与培训说明一致 |
| 通过 | ☐ |

### SC-I — 受任后客户中止

| 项 | 内容 |
|----|------|
| 背景 | 已建案，客户取消委托 |
| 数据准备 | 已有进行中的签证案件 |
| 操作步骤 | ① 将案件调至「中止/终了」等可用状态 → ② 备注记录中止日与理由 → ③ 客户主档保留，列表摘要随状态更新 |
| 预期 | 历史可追溯；主档不被误删 |
| 通过 | ☐ |

### SC-J — 老客户第二案件（再访）

| 项 | 内容 |
|----|------|
| 背景 | 数年前已结案客户再次委托 |
| 数据准备 | 历史客户 + 已终了案件 |
| 操作步骤 | ① 检索打开旧客户 → ② 新建第二件签证案件 → ③ 列表主摘要指向新活件（按 §1.11）→ ④ 旧案件仍可自详情查阅 |
| 预期 | 时间线清晰；新活件为主展示；附件不挂错旧案 |
| 通过 | ☐ |

### SC-K — 历史导入客户（若启用批量导入）

| 项 | 内容 |
|----|------|
| 背景 | Excel/CSV 导入的历史签证客户 |
| 数据准备 | 导入批次样例（脱敏） |
| 操作步骤 | ① 导入后列表检索 → ② 打开详情核对主档与案件关联 → ③ 编辑补正后保存 |
| 预期 | 与手工建档行为一致；无只读字段异常；审计/批次信息可辨（按产品设计） |
| 通过 | ☐ |
