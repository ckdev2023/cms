# 4. 案件运营系统（Admin / Staff）——按业务类型细化设计

## 4.0 设计目标

后台系统不是简单的 CRM，而是一个「事务所业务操作系统」：

- 让案件从“获客 → 受任 → 收资料 → 制作文书 → 提交申请 → 补正 → 结案 → 售后提醒”形成闭环
- 把不同业务类型做成标准模板
- 把“人员分工、截止日、资料状态、收费状态、风险控制”统一放进一个界面
- 让新人也能按 SOP 办案
- 让负责人可以看见每个案件卡在哪一步、为什么卡住、谁负责、什么时候会超期

---

# 4.1 Admin / Staff 总后台的统一模块

无论是什么业务类型，后台都建议先统一成以下模块：

## 4.1.1 案件主表（Case Master）

每个案件必须有统一主档：

### 基础字段
- 案件编号
- 案件类型
- 子类型
- 客户姓名 / 公司名
- 国籍 / 法人属性
- 委托日期
- 当前阶段
- 紧急程度
- 负责人（主担当）
- 助理担当
- 对接渠道（官网 / 微信 / LINE / 介绍 / 广告）
- 预计完成日
- 下一个关键节点
- 收费状态
- 风险等级

### 统一标签
- 新客 / 老客
- 单次委托 / 长期顾问
- 中文客户 / 日文客户 / 英文客户
- 高客单价 / 标准 / 低客单价
- 高风险 / 补件多 / 时间紧 / 审查严格

---

## 4.1.2 任务系统（Task Engine）

每个案件自动生成任务清单：

- 初谈记录整理
- 委任契约发送
- 着手金收款确认
- 文件清单发送
- 客户资料审核
- 文案草拟
- 主管复核
- 申请递交
- 补正跟进
- 结果通知
- 尾款收取
- 结案归档
- 售后提醒设置

每个任务要包含：
- 任务名称
- 所属阶段
- 责任人
- 截止日期
- 是否阻塞后续流程
- 依赖任务
- 完成条件
- 备注 / 内部说明

---

## 4.1.3 文件系统（Document Center）

统一支持：
- 客户上传
- 员工上传
- 模板生成
- 版本控制
- 审核状态
- 到期提醒

文件状态建议：
- 待客户提交
- 已提交待审核
- 审核通过
- 需补正
- 已用于申请
- 已归档

---

## 4.1.4 内部审批流

关键节点必须审批：
- 是否受任
- 是否报价
- 是否低价特批
- 是否存在拒签/拒批风险
- 是否提交申请
- 是否回复补正
- 是否允许结案
- 是否允许退款 / 减免

---

## 4.1.5 财务联动

每个案件关联：
- 报价单
- 合同
- 分期计划
- 发票
- 收款记录
- 未收款提醒
- 成本记录
- 外部费用（官费 / 公证 / 翻译 / 邮寄 / 印纸 / 交通）

---

## 4.1.6 风险控制中心

统一风控项目：
- 客户身份不明
- 文件真伪存疑
- 资料前后矛盾
- 既往拒签 / 拒批
- 税务 / 住民税异常
- 公司经营异常
- 期限即将届满
- 无法说明资金来源
- 关键附件缺失
- 非事务所业务范围事项提醒

## 4.2.J 契约书 / 内容证明 / 企业法务顾问

> 行政书士法务文书、契约书、内容证明也是官方公开业务范围的一部分。:contentReference[oaicite:8]{index=8}

### J-1 子业务

- 合作协议
- 内容证明
- 债权催告文书
- 法人议事录

- 文书模板中心
- Clause 条款库
- 多版本对比
- 内部审稿流程
- 风险条款提示
- 电子签署
- 交付回执

### J-4 典型流程
1. 需求访谈
2. 事实关系确认
3. 初稿生成

# 4.3 不同业务共用的后台“高级能力”

## 4.3.1 业务模板化引擎
每类业务都要有：
- 默认阶段
- 默认任务
- 默认文件清单
- 默认收费方案
- 默认风险项
- 默认消息模板

## 4.3.2 多案件联动
例如一个中国客户可能同时有：
- 公司设立
- 经营管理签证
- 饮食店许可
- 配偶家族滞在
- 后续永住

系统要支持“一位客户，多案件，多公司，多家属”的视图。

## 4.3.3 事务所负责人管理视角
负责人最想看的是：
- 今日即将超期案件
- 需要主管复核案件
- 本周可提交案件
- 补件停滞超过 7 天案件
- 未收款案件
- 高风险案件
- 每个员工手上的案件负荷

## 4.3.4 助理视角
助理最需要：
- 今天待催资料客户
- 今天待检查文件
- 哪些案件缺哪类文件
- 哪些案件等待主管审核
- 哪些申请已经提交但还没录入受理号

## 4.3.5 合规与安全
事务所系统会处理大量身份、户籍、在留、财务等敏感信息，因此至少应结合日本个保法体系建设权限、操作日志、安全管理、委托处理和数据规则。:contentReference[oaicite:9]{index=9}

建议最少做到：
- 角色权限控制
- 下载权限限制
- 文件水印
- 操作日志
- 敏感字段脱敏
- 外部共享链接时效
- 数据删除与归档规则
- 委托供应商管理记录

# 4.5 一个最实战的结论

真正适合大阪行政书士事务所的 SaaS，不是“通用 CRM”，而是：

> **按业务类型内置 SOP + 文件清单 + 风险规则 + 到期机制 + 文书模板 + 收费逻辑 的案件操作系统**

换句话说：

- 签证案件重点是：**期限、补件、理由书、身份资料**
- 建設業重点是：**资格要件、台账、年度维护**
- 古物商重点是：**标准化和批量效率**
- 公司设立重点是：**前置设计 + 后续许可转化**
- 相続遗言重点是：**关系图、户籍、保密**
- 饮食 / 民泊 / 风俗重点是：**物件、图面、多机关并行**
