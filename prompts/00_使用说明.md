# Cursor Prompt 使用说明

## 1. 目的

本目录用于放给 Cursor 直接使用的 Prompt。

目标是让 Cursor：

1. 先读对文档
2. 先做开发 Plan
3. 再按阶段执行
4. 每一轮都补测试和验证

## 2. 推荐使用顺序

### 第一步：先生成总开发 Plan

先把下面这个 Prompt 发给 Cursor：

- `prompts/01_Cursor_项目接手并生成开发Plan.prompt.md`

适用场景：

- Cursor 刚接手项目
- 你想让它先理解项目
- 你想先拿到完整开发 Plan，而不是立刻写代码

### 第二步：按阶段推进开发

当总 Plan 确认后，再使用：

- `prompts/02_Cursor_按阶段执行开发.prompt.md`

适用场景：

- 你已经知道现在要做第几阶段
- 你希望 Cursor 按阶段拆子任务并推进
- 你希望它每一轮都带测试和验证

### 第三步：对单模块深入开发

当你要让 Cursor 单独开发某个模块时，使用：

- `prompts/03_Cursor_单模块开发与测试.prompt.md`

适用场景：

- 开发客户中心
- 开发文件模块
- 开发财务模块
- 给某一模块补单元测试

### 第四步：使用更细粒度的阶段 / 模块 Prompt

当你已经明确要做某一阶段或某一重点模块时，可以直接使用：

- `prompts/04_Cursor_初始化工程执行.prompt.md`
- `prompts/05_Cursor_数据库落地执行.prompt.md`
- `prompts/06_Cursor_客户模块开发.prompt.md`
- `prompts/07_Cursor_文件模块开发.prompt.md`
- `prompts/08_Cursor_行政书士事务模块开发.prompt.md`
- `prompts/09_Cursor_税理士模块开发.prompt.md`
- `prompts/10_Cursor_财务模块开发.prompt.md`
- `prompts/11_Cursor_联调与回归测试.prompt.md`
- `prompts/12_Cursor_代码规范与实现要求.prompt.md`
- `prompts/13_Cursor_输出汇报格式规范.prompt.md`
- `prompts/14_Cursor_提交前检查与收口.prompt.md`
- `prompts/15_Cursor_Bug修复与最小回归.prompt.md`
- `prompts/16_Cursor_接口变更同步检查.prompt.md`
- `prompts/17_Cursor_前端页面拆分与重构规范.prompt.md`
- `prompts/18_Cursor_后端Service与DTO拆分规范.prompt.md`

适用场景：

- 你希望 Cursor 直接推进初始化工程
- 你希望 Cursor 直接推进数据库和基础权限能力
- 你希望 Cursor 专注开发客户主流程
- 你希望 Cursor 专注开发文件上传下载预览主链路
- 你希望 Cursor 专注开发行政案件主流程
- 你希望 Cursor 专注开发税务合同与月次主流程
- 你希望 Cursor 专注开发财务主流程
- 你希望 Cursor 执行联调与回归测试
- 你希望 Cursor 在写代码时严格遵守统一编码规范
- 你希望 Cursor 每轮都按统一格式汇报结果
- 你希望 Cursor 在任务结束前做固定检查和收口
- 你希望 Cursor 专门处理 bug 修复并补最小回归
- 你希望 Cursor 在改接口时同步检查前后端与测试
- 你希望 Cursor 对前端大页面做可控拆分和重构
- 你希望 Cursor 对后端大 Service / DTO 做规范化拆分

## 3. 你最常用的方式

如果你现在要让 Cursor 先做整体规划，建议直接这样用：

1. 打开 `prompts/01_Cursor_项目接手并生成开发Plan.prompt.md`
2. 复制全文给 Cursor
3. 让它先输出开发 Plan
4. 你确认后，再用 `prompts/02...` 或 `prompts/03...`

## 5. 使用建议

- 先让 Cursor 出 Plan，再让它写代码
- 一次只让它处理一个阶段或一个模块
- 每轮都要求它补单元测试
- 每轮都要求它说明读了哪些文档、改了哪些文件、跑了哪些验证

推荐组合：

1. 先用 `prompts/01...` 生成总开发 Plan
2. 再用 `prompts/02...` 推进某一阶段
3. 如果要深入执行初始化，可直接切到 `prompts/04...`
4. 如果要深入执行数据库，可直接切到 `prompts/05...`
5. 如果要深挖客户模块，用 `prompts/06...`
6. 如果要深挖文件模块，用 `prompts/07...`
7. 如果要开发行政模块，用 `prompts/08...`
8. 如果要开发税务模块，用 `prompts/09...`
9. 如果要开发财务模块，用 `prompts/10...`
10. 如果要做联调回归，用 `prompts/11...`
11. 只要涉及写代码，建议把 `prompts/12...` 和具体开发 Prompt 一起发给 Cursor
12. 只要你希望输出更规整，建议把 `prompts/13...` 一起发给 Cursor
13. 只要一轮任务准备结束，建议把 `prompts/14...` 一起发给 Cursor 做收口
14. 如果当前是修 bug，建议直接用 `prompts/15...`
15. 如果当前改了接口，建议补发 `prompts/16...`
16. 如果前端页面已经太大，建议用 `prompts/17...`
17. 如果后端 Service 或 DTO 太乱，建议用 `prompts/18...`

推荐强组合：

- 开发类 Prompt + `prompts/12...` + `prompts/13...` + `prompts/14...`
- Bug 修复 Prompt + `prompts/12...` + `prompts/13...` + `prompts/14...`
- 接口变更类 Prompt + `prompts/12...` + `prompts/13...` + `prompts/14...` + `prompts/16...`
