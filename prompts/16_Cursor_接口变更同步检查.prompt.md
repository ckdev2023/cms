你现在负责处理“接口变更同步检查”。目标是确保前端、后端、类型、文档、测试对同一接口口径保持一致，避免改了接口但遗漏上下游同步。

如需编写代码，必须同时遵守：

- `prompts/12_Cursor_代码规范与实现要求.prompt.md`
- `prompts/13_Cursor_输出汇报格式规范.prompt.md`
- `prompts/14_Cursor_提交前检查与收口.prompt.md`

## 一、适用范围

适用于：

- 新增接口
- 修改接口路径、方法、请求参数、返回结构
- 修改字段命名、枚举值、分页结构、错误码
- 修改 DTO、前端 API 类型、表单字段、详情页结构

## 二、先读取文档

至少先读：

1. `docs/06_API接口设计.md`
2. `docs/03_数据库设计.md`
3. `docs/07_权限矩阵与角色设计.md`
4. 当前模块对应的前端界面文档
5. `docs/14_复杂安全项后置与测试质量策略.md`

如仓库已有代码，请优先检查：

- 后端 controller / service / dto
- entity / schema / migration
- 前端 API 封装、类型定义、页面表单、列表、详情
- 权限配置
- 测试文件

## 三、执行顺序

### 1. 先列出接口变更清单

请明确：

- 哪个接口变了
- 变更前是什么
- 变更后是什么
- 为什么要变
- 会影响哪些上游 / 下游

### 2. 输出同步检查计划

至少覆盖：

- 后端 controller / dto / service
- 数据结构或 migration
- 前端 API 与类型
- 页面表单 / 列表 / 详情展示
- 权限判断
- 测试与文档

### 3. 再开始同步修改

修改时请遵守：

- 同一接口的前后端字段命名保持一致
- 不要只改后端不改前端，或反过来
- 如返回结构变化，相关页面和测试必须同步
- 如枚举或状态流转变化，文案、校验、筛选也要同步
- 如接口语义已变，记得同步文档说明

### 4. 必须补同步验证

至少完成：

- 相关接口测试或最小调用验证
- 前端对应页面或调用链的最小验证
- 至少一项类型或构建检查
- 如涉及权限，补最小权限验证

### 5. 最终输出

请总结：

- 本次接口变更点
- 已同步的文件与层次
- 未同步项或风险项
- 测试与验证结果
- 是否还需要补文档或补回归

## 四、限制要求

- 不要只改表面调用层，忽略 DTO / 类型 / 测试
- 不要遗漏权限与错误处理口径
- 不要对未验证的同步结果说成已完成
- 若接口变更范围不清晰，请先列影响面

请用中文输出，优先保证口径一致、上下游同步、验证完整。
