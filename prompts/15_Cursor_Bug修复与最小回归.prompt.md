你现在负责处理一个明确 bug。目标不是顺手大改，而是先复现、定位、最小修复、补最小回归验证，确保问题被解决且不扩大改动范围。

如需编写代码，必须同时遵守：

- `prompts/12_Cursor_代码规范与实现要求.prompt.md`
- `prompts/13_Cursor_输出汇报格式规范.prompt.md`
- `prompts/14_Cursor_提交前检查与收口.prompt.md`

## 一、适用范围

适用于：

- 明确报错修复
- 功能异常修复
- 接口行为与预期不一致修复
- 表单、状态流转、权限、金额、文件链路 bug 修复

## 二、先读取文档

至少先读：

1. `docs/16_AI执行总入口与任务拆解.md`
2. `docs/14_复杂安全项后置与测试质量策略.md`
3. 与当前 bug 相关的模块文档
4. 与当前 bug 相关的接口 / 权限 / 数据库文档

如仓库已有代码，请优先检查：

- 报错位置相关文件
- 调用链上下游文件
- 相关测试文件
- 日志、错误信息、请求参数、返回结构

## 三、执行顺序

### 1. 先复现问题

请明确：

- bug 现象是什么
- 触发条件是什么
- 预期行为是什么
- 实际行为是什么
- 能否稳定复现

如果无法复现，不要直接盲改，请先列出阻塞项。

### 2. 输出最小修复计划

请拆成：

- 根因假设
- 需要检查的文件
- 最小改动点
- 可能影响的链路
- 最小验证方案

### 3. 再开始修复

修复时请遵守：

- 优先最小改动，不做顺手重构
- 不把一个 bug 修复扩展成大面积功能改造
- 根因不明确时，不要靠堆 if 临时糊住
- 涉及权限、财务、文件时要更保守
- 如果修复需要同步接口、类型、测试，请一起处理

### 4. 必须补最小回归

至少完成：

- 一个能覆盖该 bug 的最小测试或验证
- 一个相关主链路的最小 smoke check
- 如有原测试失败，修复后重跑相关测试

### 5. 最终输出

请明确说明：

- bug 根因
- 实际修复方式
- 修改文件列表
- 测试与验证结果
- 是否还有残余风险
- 是否建议继续补更大范围回归

## 四、限制要求

- 不要跳过复现环节就直接改代码
- 不要在一次 bug 修复中顺手改太多无关逻辑
- 不要省略测试与最小回归
- 若无法确定根因，请先列待确认项

请用中文输出，优先保证修复准确、改动最小、验证明确。
