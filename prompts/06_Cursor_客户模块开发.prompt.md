## 二、默认前提

请默认接受这些前提：

- 本轮优先做“客户中心主链路”
- 前端以 `Vue 3 + Element Plus` 为准
- 后端以 `NestJS + PostgreSQL` 为准
- 主流程优先于增强项
- 本轮先不做复杂导入导出、复杂审批、复杂统计

1. 客户列表

4. 客户详情

## 四、请按以下顺序工作

### 1. 先输出模块理解

请先说明：

- 客户模块在系统中的角色
- 本轮明确要做的范围
- 本轮不做的范围
- 依赖哪些基础能力（登录、RBAC、数据库、公共组件等）

### 2. 输出实施计划

请将本轮拆成子任务，例如：

- 数据结构与接口
- 列表页
- 新建 / 编辑表单
- 详情页
- 权限与交互
- 测试与验证

每个子任务要写：

- 目标
- 涉及文件
- 风险点
- 完成标准

### 3. 再开始实现

实现时请遵守：

- 先打通列表 → 新建 → 编辑 → 详情闭环
- 前后端字段保持一致
- 客户编码、名称、类型、联系方式、负责人等关键字段优先稳定
- 复杂增强项后置
- 如需改 API 或表结构，记得同步类型和测试

### 4. 必须补测试

至少完成：

- 后端 service 关键逻辑测试
- 客户接口最小测试
- 前端关键表单或列表交互测试
- 至少一轮主流程 smoke check

### 5. 最终输出

请总结：

- 本轮完成的客户能力
- 修改文件列表
- 测试与验证结果
- 未完成项
- 下一轮建议（例如：备注、关系、日志、导出等）

## 五、限制要求

- 不要直接扩展到行政 / 税务 / 财务模块
- 不要先做复杂统计报表
- 不要省略测试
- 如果客户字段口径不明确，请先列出待确认项

请用中文输出，优先保证客户主流程稳、可用、可测试。
