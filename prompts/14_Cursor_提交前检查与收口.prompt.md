你在结束本轮开发、修复、联调或测试任务前，必须执行以下“提交前检查与收口”流程。目标是避免把半成品、漏测代码、超长文件、临时代码或错误结论带到下一轮。

## 一、适用范围

适用于：

- 阶段开发完成前
- 单模块开发完成前
- bug 修复完成前
- 联调回归结束前
- 准备合并或交付前

## 二、总体原则

- 先检查，再宣称完成
- 先最小验证，再扩大范围
- 先修明显问题，再输出总结
- 对未验证事项必须明确标注，不可假设通过

## 三、提交前检查清单

### 1. 范围检查

确认：

- 本轮是否只做了约定范围内的事
- 是否误改了不相关文件
- 是否越界修改了共享基础文件
- 是否有本不该本轮实现的增强项被提前加入

### 2. 代码规范检查

确认：

- 命名是否清晰
- 是否存在明显大函数 / 大文件
- 是否存在过深嵌套
- 是否保留了调试代码、无意义注释、注释掉的大段旧代码
- 是否补了必要注释与 TODO 原因说明

### 3. 健壮性检查

确认：

- 输入校验是否补齐
- 错误处理是否明确
- 空值、重复提交、权限不足、边界值是否考虑到
- 高风险动作是否有保护逻辑

### 4. 性能与数据链路检查

确认：

- 是否出现明显重复查询、重复计算、循环内 I/O
- 列表是否分页
- 搜索或高频输入是否需要防抖 / 节流
- 数据库关键筛选字段是否需要索引
- 财务 / 文件 / 权限链路是否保持可追踪

### 5. 类型、构建与测试检查

尽量执行并记录：

- 单元测试
- 接口或集成测试
- 前端关键交互测试
- 构建 / 类型检查 / lint
- 最小 smoke check

如果因环境阻塞无法执行，必须明确写出阻塞原因。

### 6. 文件清单检查

确认：

- 修改文件列表是否完整
- 新增文件是否确实需要
- 是否残留临时文件、假数据文件、实验文件
- 是否有应该拆分但尚未拆分的大文件

### 7. 文档与说明检查

确认：

- 如果改了接口、字段、流程，是否同步更新相关文档或说明
- 输出总结是否说明了测试结果和风险
- 输出是否遵守 `prompts/13_Cursor_输出汇报格式规范.prompt.md`

## 四、收口动作

在最终汇报前，请执行以下动作：

1. 列出本轮实际完成项
2. 列出未完成项
3. 列出已验证项和未验证项
4. 列出风险项
5. 给出最具体的下一步建议

## 五、发现问题时的处理原则

- 如果是小问题，优先直接修复后再汇报
- 如果是范围外问题，明确标注，不要顺手扩散开发
- 如果是环境问题，写明阻塞项和建议处理方式
- 如果是不确定的业务口径，先列待确认项，不要强行拍脑袋实现

## 六、禁止事项

- 未检查就说“已完成”
- 未测试就说“已验证”
- 漏写失败项和风险项
- 漏写修改文件列表
- 明知存在超长函数 / 临时代码仍不说明

请把这个检查流程作为每轮任务结束前的固定动作，确保结果稳、清晰、可交付。
