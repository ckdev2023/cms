# AI执行总入口与任务拆解

## 1. 文档目标

本文是整个项目的总入口文档。

用途不是补充某一块细节，而是告诉 AI 和开发者：

1. 现在第一步先做什么
2. 应该先看哪些文档
3. 第二步做什么
4. 每个大阶段要拆成哪些子任务
5. 怎样在高效的同时保证质量
6. 代码规范和 JSDoc 门禁的要求与校验命令

如果后续你让任何 AI 接手项目，建议先从本文开始。

> **注意**：本文件是路线图与任务拆解文档。AI 接手时的唯一总入口为仓库根的 `AGENTS.md`，其中包含校验命令、代码规范和 JSDoc 规范的完整摘要。

任何 AI 接手时，默认按下面顺序处理。

### 第一步：先理解项目，不要急着写代码

先看这些文档：

1. `docs/事务所管理系统_需求分析与开发说明.md`

目的：明确当前应该处于哪个阶段，以及哪些事情能并行、哪些必须串行。

### 第三步：按当前阶段读取专项文档

根据正在做的事情，再补读对应文档：

## 3. AI 的总执行原则

任何阶段都遵守下面 6 条：

1. 先确认边界，再改代码
2. 先做主流程，再补增强项
3. 先做公共基础，再做业务模块
4. 先补单元测试，再合并收口
5. 能小步完成就不要一次改太大
6. 遇到关键业务口径不明确时，先停下来确认

## 14. AI 每次开始工作前的检查清单

每次开始一轮新任务前，先确认：

1. **阅读总入口**：先读 `AGENTS.md`（仓库根），确认校验命令和当前规范。
2. **确认大阶段**：当前属于哪个大阶段（见本文 §4）。
3. **确认前置条件**：本阶段的前置条件是否已完成。
4. **按需补读文档**：
   - 代码规范：`docs/s05_style_rules.md`（ESLint 规则分级）。
   - JSDoc 标准：`docs/s06_jsdoc_standard.md`（必填字段和模板）。
   - JSDoc 门禁：`docs/s07_jsdoc_gate_design.md`（两层自动检查）。
   - 业务模块：按需查阅 `docs/02_` ~ `docs/07_` 系列。
5. **列出修改文件**：评估是否与其他窗口/分支冲突。
6. **确认校验范围**：本轮结束后至少需要通过 `npm run verify:fast`。

## 15. AI 每次提交前的检查清单

每次准备交付一轮结果前，确认：

1. **本轮目标已完成**。
2. **没有修改不该动的公共文件**（路由配置、全局样式、TypeORM 配置等）。
3. **已补对应单元测试**（如涉及业务逻辑）。
4. **代码规范通过**：新增/修改代码符合 `docs/s05_style_rules.md` 中的规则。
5. **JSDoc 完整**：新增/修改的方法已按 `docs/s06_jsdoc_standard.md` 的模板补齐 JSDoc（用途描述、`@param`、`@returns`、`@throws`）。
6. **运行校验命令**（三选一，按交付级别递进）：

   | 交付场景 | 命令 | 包含检查 |
   |---------|------|---------|
   | 日常开发 | `npm run verify:fast` | lint（含 JSDoc 存在性）+ type-check + JSDoc 质量检查 |
   | 功能完成 | `npm run verify` | verify:fast + 前后端测试 |
   | 发布/部署前 | `npm run verify:full` | verify + 前后端构建 |

7. **必要文档已同步更新**。
8. **说明下一步建议**。

## 16. 代码规范与 JSDoc 门禁

本项目已建立"代码规范 + JSDoc 质量"双重自动门禁，所有新增或修改的代码必须满足：

### 代码规范（详见 `docs/s05_style_rules.md`）

- **阻断级（error）**：`debugger`、`alert()`、`eval()`、强制 `===`、Vue `<script setup>` 块顺序等 — lint 不通过即阻断交付。
- **渐进级（warn）**：`no-console`、导入排序、未使用变量、`no-explicit-any`、文件/函数长度守卫 — 新增代码应避免，预存问题渐进清理。

### JSDoc 标准（详见 `docs/s06_jsdoc_standard.md`）

- **强制范围**：前端 `stores/`、`composables/`、`utils/`、`api/`；后端 `*.service.ts`、`*.controller.ts`、`guards/`、`interceptors/`、`helpers/`、`filters/`。
- **必填字段**：用途描述（正文首行）、`@param` 逐项说明、`@returns` 返回值、`@throws` 副作用。
- **禁止空泛描述**（"处理数据"、"获取信息"等），有效字符不少于 8 个。

### 两层自动检查（详见 `docs/s07_jsdoc_gate_design.md`）

- **Layer 1**（ESLint `eslint-plugin-jsdoc`）：随 `npm run lint` 执行，检查存在性与结构。
- **Layer 2**（`scripts/check-jsdoc.mjs`）：随 `npm run jsdoc:check` 执行，检查内容质量。
- 两层均已集成到 `npm run verify:fast` 管道中。

## 17. 推荐使用方式

如果你后面要让 AI 实际开工，最推荐的用法是：

1. 先把本文发给 AI
2. 再告诉 AI 当前处于哪个大阶段
3. 再让 AI 只执行该阶段下的一组子任务
4. 完成后先验收，再进入下一个阶段

这样比“让 AI 自己猜应该先做什么”更稳很多。
