# P2-S3g：迁移 / 入口合并验收

> **文档定位**：计划 **P2-S3g** 产出。在 **不修改** `签证客户中心计划优化` 计划文件的前提下，给出 **抽样对比、权限、深链书签、回滚（若适用）** 的可执行验收清单，与 **`docs/21`**、**`docs/26`**、**`docs/28`**、**`docs/29`** 口径一致。  
> **范围说明**：当前基线 **无** `admin_cases` → `visa_cases` 的默认全量迁移；验收以 **双轨数据并存 + 导航层合并（P2-S3e）+ 可选嵌入（P2-S3b）+ 构建期入口开关（P2-S3f）** 为主。若日后上线 **P2-S3d** 行政→签证补录工具，须在本清单 **§6** 追加批次级验收与回滚演练。

## 1. 验收前提（必须与冻結文档一致）

| 条款 | 出处 | 验收时核对 |
|------|------|------------|
| `admin_cases` 与 `visa_cases` 并列域；不删 `/admin-cases/*` | `docs/21` §1、§3.2；`docs/29` §2.1 | API 与页面仍可用 |
| 旧在留提醒仍基于 `person_info.residence_expire_date`；新提醒基于 `visa_cases.expire_date` | `docs/21` §6.4；`docs/28` §1 | 同一客户上两口径可 **同时有数据且不强制相等** |

| 侧栏合并分组内 **并列** 行政与签证入口 | `docs/29` §3；`MainLayout` 实现 | 有权限的用户可见对应子项 |

## 2. 抽样对比（同一客户四视角）

对 **至少 3 名** 真实或种子客户（建议覆盖：仅有行政案件、仅有签证案件、两者皆有、皆无）记录下列字段，**不要求** 条数或日期一致，但须 **能解释差异**（见 `docs/28` §1、§2）。

| # | 检查项 | 数据来源 / 操作 | 期望 |
|---|--------|-----------------|------|
| 2.1 | 客户主档在留到期 | 客户详情基本资料或 `person_info` | 与旧提醒口径一致时可核对 |
| 2.2 | 旧提醒是否命中 | `GET /customers/residence-expiry-reminders` 或 `/customers/residence-reminders` | 与 2.1 一致或符合列表规则 |
| 2.3 | 签证提醒是否命中 | `GET /visa-reminders` 或 `/visa-reminders` | 仅与 `visa_cases` 生命周期相关 |
| 2.4 | 行政案件条数 | 客户详情行政域或 `GET /admin-cases?customerId=`（以实际 API 为准） | 条数独立统计 |
| 2.5 | 签证案件条数 | `GET /customers/{id}/visa-cases` 或客户详情签证 Tab | 条数独立统计 |
| 2.6 | 可选：人工 / 工具补录后 | 若执行过 P2-S3d 或向导建案 | 签证侧新增/更新可追溯；**行政侧记录未被自动删除** |

**记录模板（可复制）**

```text
客户 ID：________
person_info.residence_expire_date：________
旧提醒列表是否包含该客户：是 / 否（截图或接口片段）
新提醒列表是否包含该客户任一案件：是 / 否
admin_cases 条数：____   visa_cases 条数：____
差异说明（一句话）：________
```

## 3. 权限与可见性

### 3.1 路由元权限（与书签行为）

以下路径的 **路由 meta.permissions** 在 `frontend/src/router/routes.ts` 中定义；无权限用户应被守卫挡至 403（或项目约定行为），**不因菜单隐藏而误以为接口关闭**。

| 路径 | 典型权限依赖 | 验收动作 |
|------|----------------|----------|
| `/visa-reminders` | `visaReminder:list` | 仅签证提醒角色：可进；无该权限：403 |
| `/customers/residence-reminders` | `customer:list` | 仅有客户列表、无签证提醒：可进旧页 |
| `/visa-reminders?reminderPanel=personResidence` | `visaReminder:list` **且** 嵌入需 `customer:list`（见 `VisaReminderListView`） | 无 `customer:list` 时不应仅靠 query 绕过嵌入规则 |
| `/workbench/visa` | `visaReminder:list` **或** `visaCase:list` | 命中其一即可 |
| `/visa-cases` | `visaCase:list` | |
| `/admin-cases`、`/admin-cases/:id` | `admin_case:list` / `admin_case:detail` | 与签证权限 **解耦** |
| `/customers/:id`（签证 Tab） | `customer:detail` + 各签证子权限 | 只读/编辑与种子角色一致 |

### 3.2 构建期开关（P2-S3f）与权限的组合

环境变量见 `frontend/.env.example`：`VITE_VISA_UI_LEGACY_RESIDENCE_VISIBLE`、`VITE_VISA_UI_VISA_PRIMARY_VISIBLE`。

| 场景 | 期望 |
|------|------|
| 开关关闭：侧栏隐藏旧在留或签证主路径子项 | 用户 **仍可直接输入 URL** 打开 `/customers/residence-reminders` 等（产品约定：不配置路由守卫隐藏） |
| 无 `visaReminder:list` 仅有 `customer:list` | 仍可访问旧在留页；签证提醒页不可（403） |
| `VisaRelatedEntryLinks`（客户详情旁） | 仅在有对应权限且 `visaUiLegacyResidenceEntriesVisible()` 等为 true 时显示 |

## 4. 深链书签（须持续有效）

在 **生产或预发基路径** 下替换 `{origin}` 后整链访问（History 模式示例如下；若部署带 `base`，自行前缀）。

| # | 用途 | 路径与 query |
|---|------|----------------|
| D1 | 旧在留独立页 | `{origin}/customers/residence-reminders` |
| D2 | 签证提醒默认面板 | `{origin}/visa-reminders` |
| D3 | 签证提醒页直接打开「在留期限（客户主档 · 旧版）」嵌入标签 | `{origin}/visa-reminders?reminderPanel=personResidence` |
| D4 | 签证工作台 | `{origin}/workbench/visa` |
| D5 | 全局签证案件登记 | `{origin}/visa-cases` |
| D6 | 行政案件列表 | `{origin}/admin-cases` |
| D7 | 客户详情（用于 Tab 深链若项目已支持 hash/query） | `{origin}/customers/{id}` |

**验收**：每个链接在 **已登录且具备对应权限** 的账号下 **一次刷新** 即到达预期界面，无无限重定向、无空白壳层。

## 5. 回滚（若适用）

### 5.1 仅代码层：入口合并 / 嵌入 / 侧栏分组

- **性质**：前端路由与菜单重组，**无** 配套 schema 迁移时，回滚方式为 **回滚部署到上一前端构建产物**（参见 `docs/19_ロールバック手順書.md` **L1/L2**）。
- **数据**：不要求数据库回滚。

### 5.2 构建期开关应急

- 不改变 Git 版本时，可通过重新构建并设置 `VITE_VISA_UI_*=false` 或 `true` 恢复侧栏可见性（见 `frontend/src/utils/visa-ui-feature-flags.ts`）。
- 验证：开关切换后侧栏与引导链变化符合 §3.2，深链仍可用。

### 5.3 若已使用 P2-S3d 批量补录工具（未来）

- **必须**保留：dry-run 结果、批次 ID、操作者、时间窗口。
- **回滚策略**（择一并在运维文档中写明）：  
  - **业务回滚**：按批次号执行工具或脚本提供的 **反向删除/标记作废**（若有）；或  
  - **库表还原**：仅当上线前全库备份时，按 `docs/19` **L3** 在维护窗口恢复；**禁止** 与行政域混为「单表回滚」。
- 本清单 §2 抽样客户应在补录 **前后** 各记录一行，便于审计对比。
