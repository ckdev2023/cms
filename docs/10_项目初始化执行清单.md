# 事务所管理系统项目初始化执行清单

## 1. 文档目标

本文用于细化“项目从 0 到可启动”的执行步骤。

适用场景：

- 准备正式开始开发
- 需要建立统一代码结构
- 需要让前后端与数据库都能本地启动

## 2. 初始化目标

完成本清单后，应达到以下状态：

1. 前端项目可本地启动
2. 后端项目可本地启动
3. 数据库连接已打通
4. 基础目录结构已固定
5. 环境变量模板已准备
6. 仓库可作为后续模块开发基础

## 3. 推荐初始化范围

建议先建立以下目录：

- `frontend`：Vue 3 管理后台
- `backend`：NestJS 服务端
- `docs`：需求与开发文档
- `scripts`：初始化脚本、数据脚本、部署辅助脚本

如果项目只用单仓库管理，这个结构最清晰。

## 4. 执行步骤

### 4.1 步骤 01：确认本地开发环境

目标：保证开发人员机器具备最基本的运行条件。

具体操作：

- 安装稳定版本 Node.js
- 确认使用统一包管理工具，如 `pnpm` 或 `npm`
- 确认 Git 可正常使用
- 确认本地可连接 PostgreSQL
- 如果采用 Access 备选方案，确认驱动和访问方式

对应技能：

- Node.js 基础
- 命令行基础
- Git 基础
- 数据库客户端使用

产出物：

- 开发环境确认表
- 统一工具版本说明

完成标准：新成员按说明可完成本地环境准备。

### 4.2 步骤 02：初始化代码仓库结构

目标：建立统一的项目根目录规范。

具体操作：

- 创建 `frontend`、`backend`、`docs`、`scripts` 目录
- 统一 `.gitignore` 规则
- 建立根目录 `README.md`
- 约定分支命名、worktree 使用方式、提交命名和模块命名方式

对应技能：

- Git 仓库管理
- 工程目录设计
- 团队协作规范制定

产出物：

- 初始仓库结构
- 根目录说明文档

完成标准：仓库目录清晰，所有开发人员理解主目录用途。

### 4.3 步骤 03：初始化前端项目

目标：搭建 Vue 3 管理后台骨架。

具体操作：

- 使用 Vite 初始化 Vue 3 + TypeScript 项目
- 安装 Element Plus、Vue Router、Pinia、请求库
- 建立 `src/layouts`、`src/views`、`src/components`、`src/api`、`src/stores`、`src/types` 目录
- 配置别名、全局样式和基础请求封装
- 配置 Vitest 和基础组件测试示例
- 准备登录页、空白工作台页和主布局页

对应技能：

- Vue 3
- TypeScript
- Vite
- Element Plus
- 前端工程组织能力

产出物：

- 可启动前端骨架
- 基础页面结构
- 通用请求封装

完成标准：前端可正常运行并看到后台基础布局。

### 4.4 步骤 04：初始化后端项目

目标：搭建 NestJS 服务端骨架。

具体操作：

- 初始化 NestJS 项目
- 建立 `auth`、`customer`、`admin-case`、`tax`、`finance`、`file`、`system`、`log` 模块目录
- 接入配置管理、日志、全局异常处理、参数校验
- 保留 Jest / Nest Testing 的基础测试目录和示例
- 统一 API 前缀为 `/api/v1`
- 预留 Swagger/OpenAPI 接口文档能力

对应技能：

- NestJS
- REST API 设计
- 后端基础架构搭建
- 参数校验与异常处理

产出物：

- 可启动后端骨架
- 基础模块目录
- 基础中间件与全局配置

完成标准：后端启动后可访问健康检查或示例接口。

### 4.5 步骤 05：配置环境变量与多环境模板

目标：避免把配置写死在代码中。

具体操作：

- 规划开发、测试、生产环境配置项
- 至少包含数据库连接、端口、文件目录、鉴权密钥等变量
- 建立 `.env.example` 模板
- 明确哪些配置仅本地保存，哪些可提交仓库

对应技能：

- 环境变量管理
- 基础安全意识
- 多环境配置设计

产出物：

- 前端环境变量模板
- 后端环境变量模板
- 配置说明文档

完成标准：开发人员复制模板后即可完成本地配置。

### 4.6 步骤 06：接入数据库连接与 ORM/SQL 方案

目标：让后端具备访问数据库的能力。

具体操作：

- 确认使用 ORM 或 SQL 方案
- 配置 PostgreSQL 连接
- 建立数据库连接测试
- 约定迁移脚本目录和执行方式
- 如果客户坚持 Access，单独记录连接限制和兼容风险

对应技能：

- PostgreSQL 基础
- ORM/SQL 使用
- 数据源配置
- 数据库迁移管理

产出物：

- 数据库连接配置
- 数据库连接测试结果
- 迁移执行说明

完成标准：后端启动后可成功连接数据库。

### 4.7 步骤 07：建立基础公共能力

目标：为后续模块开发减少重复工作。

具体操作：

- 建立统一返回结构
- 建立统一分页参数和分页返回结构
- 建立统一错误码和提示信息规则
- 建立登录态拦截、请求头注入、错误提示处理
- 建立基础权限编码常量和枚举管理方式

对应技能：

- 接口规范设计
- 前后端协同规范
- 公共模块抽象能力

产出物：

- 通用 API 返回结构
- 分页与错误码约定
- 公共枚举和常量文件

完成标准：后续业务模块可以直接复用基础能力。

### 4.8 步骤 08：完成初始化阶段验收

目标：确认项目已经具备正式进入业务开发的条件。

具体操作：

- 检查前端是否能启动
- 检查后端是否能启动
- 检查数据库是否连接成功
- 检查 Swagger 或接口示例是否可访问
- 检查前后端基础单元测试是否能运行
- 检查基础目录、环境变量模板、README 是否齐全

对应技能：

- 项目联调
- 基础问题排查
- 文档整理

产出物：

- 初始化验收记录
- 初始化问题清单

完成标准：项目达到“可开始开发客户模块”的状态。

## 5. 推荐依赖清单

### 5.1 前端建议依赖

- Vue 3
- TypeScript
- Vite
- Element Plus
- Vue Router
- Pinia
- Axios 或同类请求库
- Vitest
- Vue Test Utils

### 5.2 后端建议依赖

- NestJS
- 配置管理库
- 参数校验库
- 密码加密库
- JWT 或 Session 相关依赖
- PostgreSQL 驱动
- Swagger/OpenAPI 相关依赖
- Jest / Nest Testing 相关依赖

## 6. 初始化阶段常见风险

### 6.1 目录一开始就混乱

解决建议：先固定主目录和模块命名，再开始业务开发。

### 6.2 环境变量不统一

解决建议：所有本地变量都从 `.env.example` 复制，不允许口头传递配置。

### 6.3 数据库连接先不做导致后面返工

解决建议：初始化阶段必须打通数据库连接，不要拖到第一个模块开发时再处理。

### 6.4 Access 直接作为正式主库

解决建议：如必须使用 Access，也应记录限制，并保留切换 PostgreSQL 的可能。

## 7. 初始化阶段交付检查表

建议至少逐项确认：

1. 前端项目可启动
2. 后端项目可启动
3. API 前缀已统一
4. 数据库连接成功
5. 前端基础单元测试可执行
6. 后端基础单元测试可执行
7. 环境变量模板已提交
8. 基础目录已固定
9. 根目录 README 已补齐
10. 至少 1 个示例接口可访问

## 8. 结论

项目初始化不是“把项目跑起来就算完”，而是要为后续所有模块开发打好基础。

一句话总结：**初始化阶段做得越规范，后面客户、业务、财务模块开发越顺。**
