# P2-S3a：旧在留提醒 / 行政案件 与 签证域 差距与映射评估

> **文档定位**：计划 **P2-S3a** 产出。在 **不承诺** 自动迁移的前提下，对比 **旧在留提醒** 与 **签证提醒**、**`admin_cases`** 与 **`visa_cases`** 的数据语义与结构，给出 **可映射字段**、**不可 1:1 迁移项** 与 **后续 P2-S3b–S3g 路径建议**。  
> **上游口径**：签证域边界与兼容说明见 `docs/21_签证客户中心P0验收与Rollout说明.md`；P1 旧入口弱化见 `docs/26_P1旧入口弱化策略口径冻結_P1-S5a.md`。

## 1. 旧在留提醒 vs 新签证提醒

### 1.1 并排对比

| 维度 | 旧在留提醒 | 新签证提醒（签证域） |
|------|------------|----------------------|
| **入口** | `/customers/residence-reminders`（旧页）；API `GET /customers/residence-expiry-reminders` | `/visa-reminders`；API `GET /visa-reminders` |
| **数据锚点** | 客户主档一人一档：`person_info` | 案件主档：`visa_cases`（挂在 `customer_id` 下） |
| **到期基准字段** | `person_info.residence_expire_date` | `visa_cases.expire_date`（**外部主申**的 `external_primary_expire_date` **不参与**新提醒桶） |
| **提醒逻辑** | 以在留到期日为驱动的客户列表/提醒（实现细节见客户模块） | **四类桶** + 去重优先级：补件 > 今日待跟进 > 7 天内到期 > 2 个月内到期；可结合 `case_status` 与案件日志结构化字段 |
| **权限** | 随客户中心可见性（典型 `customer:list` 等） | `visaReminder:list`（可与 `visaCase:list` 等组合） |
| **与行政案件** | 无直接耦合 | 无直接耦合 |

### 1.2 语义差距（为何不能「关掉旧页」即等同新页）

1. **粒度**：旧提醒是 **人/在留卡到期**；新提醒是 **签证案件生命周期**（一案多状态、补件、跟进时间）。同一客户 **0 个或多个** `visa_cases`，与 **1:1 的 person_info** 不对齐。
2. **字段含义**：`residence_expire_date` 表示 **当前在留资格到期**；`visa_cases.expire_date` 表示 **该签证案件维度的到期/关键日**（业务上可能是许可到期、在留届满等，由所内录入约定），**两者不保证同值**。
3. **外部主申**：家庭签外部主申仅快照在 `visa_cases`，**无客户主档**；旧在留提醒 **仅覆盖系统内客户 + person_info**，无法覆盖同一业务故事的全部角色。
4. **并存策略（已冻结）**：P0/P1 明确 **旧页不替换**；评估结论维持 **双轨并存**，迁移属 P2 可选路径，需单独产品与法务/业务确认。

### 1.3 若未来做「数据层合并展示」的可行方向（非承诺）

| 方向 | 说明 | 风险 |
|------|------|------|
| **A. 只读聚合页** | 同屏并列「在留到期（person）」与「签证提醒（visa_case）」跳转链接 | 低；不迁移数据 |
| **B. 录入联动** | 建案或更新案件时 **提示** 同步更新 `residence_expire_date` | 中；易不同步、需明确主数据归属 |
| **C. 批量回填** | 用规则从 `visa_cases.expire_date` 写回 `person_info` | 高；多案件、多家属时规则难统一 |

**建议**：在 P2-S3b 选型前，以 **A** 为默认；**B/C** 需书面主数据口径。

## 2. `admin_cases` vs `visa_cases`

### 2.1 业务定位差异（映射的前提）

| 维度 | `admin_cases`（行政案件） | `visa_cases`（签证案件） |
|------|---------------------------|---------------------------|
| **产品用途** | 行政书士侧案件：名称、在留种类文字、办理状态、负责人、到期日；面谈 / 任务 / 文档子表 | 签证客户中心主对象：案件类型/状态枚举、家庭签模式、主申（内/外）、家属挂载、材料/费用摘要、导入幂等等 |
| **状态枚举** | `AdminCaseStatus`（行政流水线） | `VisaCaseStatus`（签证流水线，含补件等） |
| **子实体** | `admin_case_interviews`、`admin_case_tasks`、`admin_case_documents` | `visa_case_family_members`、案件日志（`notes` + `visa_case_id`）、`customer_file_paths`（可挂案件） |

二者 **并列域**，计划文档已冻结 **P0 不迁移**；本评估用于 P2 若要做 **入口合并或部分映射** 时的依据。

### 2.2 字段级对照（启发式，非强制转换表）

| `admin_cases` | `visa_cases` | 映射备注 |
|---------------|--------------|----------|
| `customer_id` | `customer_id` | 可直接对齐 **归属客户** |
| `case_name` | 无同名；可选 `memo` / 未来扩展显示名 | **语义不等价**；行政「案件名」≠ 签证「案件类型」字符串 |
| `applicant_name` | 内部主申可由 `internal_primary_customer_id` + 客户主档推导；或外部 `external_primary_name` | **不自动等价**；行政申请人名未必等于系统客户姓名 |
| `residence_status` | `case_type`（varchar）可手工填接近文案 | **类型系统不同**（自由文本 vs 签证域字典/习惯取值） |
| `status`（行政） | `case_status`（签证） | **枚举值不兼容**，需 **人工映射表** 或仅「新建为 DRAFT/IN_PROGRESS」类弱映射 |
| `expire_date` | `expire_date` | 日期可拷贝作为 **初始值**，业务上仍需人工确认 |
| `owner_user_id` | `assigned_to` | UUID 维度一致，可作为 **负责人迁移** 候选 |
| `created_by` / `updated_by` | `created_by` / `updated_by` | 可对齐 |

### 2.3 不可自动迁移或高损失项

| 类别 | 说明 |
|------|------|
| **面谈记录** | `admin_case_interviews` 无 `visa_cases` 侧对等主表；迁入需新模型或长期挂行政侧 |
| **任务** | `admin_case_tasks` 同理；签证域待办目前依赖案件状态 + 日志 + 提醒桶，**非同一任务模型** |
| **行政文档** | `admin_case_documents` 与 `files` / 路径台账 `customer_file_paths` **模型不同**；迁移需重新定义「是否复制文件指针」 |
| **一行行政案 → 多签证案** | 行政侧一条可能对应多次申请；**无法保证 1:1** |
| **一行签证案 ← 零行政案** | 新流程可能仅有 `visa_cases`；反向合并亦不对齐 |

### 2.4 若 P2 需要「降级映射」的务实结论

- **1:1 自动迁移**：**不推荐** 作为默认；仅适合 **人工勾选 + 分批工具**（可复用 P1-S3 模式）且 **接受** 子表不落签证域。
- **入口合并（弱耦合）**：侧栏/客户详情 **导航合并** 不强制表合并；`docs/26` 已限定 **仅弱化排序与文案，不删 API**。
- **强统一（数据模型合并）**：超出当前冻结范围，需 **新计划** 修订 `docs/21` 职责边界后再开发。

## 3. 对 P2-S3 下游任务的输入摘要

| 子任务 | 本评估提供的输入 |
|--------|------------------|
| **P2-S3b** | 旧提醒：并列展示或嵌入 iframe/路由切换优先于字段合并 |
| **P2-S3c** | **权威冻結见 `docs/29_P2-S3c_行政案件与签证域策略口径冻結.md`**（默认独立域+入口合并；可选人工/工具字段级补录；子表默认不迁） |
| **P2-S3d** | 任何迁移工具须支持 **dry-run、幂等键、行级失败跳过** |
| **P2-S3e** | 验收需含：**双轨提醒同时存在**、行政案件链接仍可用 |
| **P2-S3f** | 若需功能开关，建议只控 **入口可见性**，不静默删数据 |
| **P2-S3g** | 验收清单：**`docs/30_P2-S3g_迁移与入口合并验收.md`**（四视角抽样、权限、深链、回滚） |
