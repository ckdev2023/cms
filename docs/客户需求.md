# 客户中心需求

## 客户中心模块定位

这是一个给日本签证 / 行政书士公司内部员工使用的后台管理系统。  
第一阶段只做客户中心，不做财务、税务、个人中心。

客户中心的目标是解决：

- 客户信息分散在微信、LINE、Excel 中
- 跟进记录容易遗漏
- 同事之间信息不同步
- 材料管理混乱
- 签证到期和续签提醒容易错过
- 客户扫描资料保存在本地服务器，系统内不好快速定位

## 一、客户中心的核心功能范围

**与实现口径**：下文出现的「护照号」「护照信息」指 **自然人身份主数据**（是否入库、落表、唯一性、隐私与检索）以 **`docs/17_业务口径冻结确认表.md` §1.12** 为权威；**当前代码尚未落库该字段**。§5「护照是否已收 / 已扫描」属于 **材料 checklist**，表示资料是否到齐与是否扫描归档，**不能**替代护照号码是否在主档中录入。

### 1. 客户档案管理

用于录入和查看客户基本信息。

客户可能是：

- 主申请人
- 家属申请人
- 独立来办理家族签的人

基础信息包括：

- 客户编号
- 姓名
- 性别
- 出生日期
- 国籍
- 联系方式
- 微信
- LINE
- 护照号（**仅个人客户**；主数据落点见 `docs/17` §1.12；实现待迭代）
- 在留卡号
- 当前在留资格
- 签证到期日
- 负责人
- 备注

### 2. 业务类型管理

目前系统只考虑这 6 类业务：

- 工作签
- 高度人才
- 经营管理签
- 家族签
- 永住申请
- 归化申请

其中家族签有两种情况：

#### 情况 A：依附本公司办理的主申请人

例如主申请人在你们这里办经营管理签，配偶和孩子在同一个案件体系下办理家族签。

#### 情况 B：主申请人不在你们公司办理

例如主申请人的工作签是别的事务所做的，但配偶和孩子单独来你们这里办理家族签。

所以系统必须支持：

- 家族签关联“内部主申请人”
- 或关联“外部主申请人”

### 3. 主申请人 + 家属成员结构

一个案件可以包含：

- 1 个主申请人
- 0 到多个附属家属成员

家属成员支持：

- 配偶
- 子女1
- 子女2
- 子女3
- 其他家属

每个成员都需要独立信息：

- 姓名
- 关系
- 出生日期
- 国籍
- 护照信息（同上，以 `docs/17` §1.12 为准）
- 当前状态
- 材料情况

### 4. 案件管理

每个客户 / 家庭会有具体签证案件。

案件字段包括：

- 案件编号
- 业务类型
- 主申请人
- 是否包含家属
- 家属人数
- 当前状态
- 材料状态
- 补件状态
- 收费状态
- 签证到期日
- 下次跟进时间
- 负责人
- 创建时间

案件状态建议：

- 初次咨询
- 材料准备中
- 材料已收齐
- 已提交
- 审核中
- 需要补件
- 已获批
- 已完成
- 已中止

### 5. 材料状态管理

系统第一阶段不直接存文件，只管理材料状态和本地服务器路径。

需要记录（**材料到位与扫描状态**，与主档「护照号码」字段无关，互引 `docs/17` §1.12）：

- 护照是否已收
- 护照是否已扫描
- 在留卡是否已收
- 在留卡是否已扫描
- 住民票是否已提交
- 纳税资料是否已提交
- 其他材料是否齐全
- 是否需要补件
- 缺少哪些材料
- 补件截止日

### 6. 本地服务器资料路径关联

你们的扫描件继续保存在本地服务器。  
第一阶段采用最简单方案：

在客户详情页 / 案件详情页显示本地服务器文件夹路径。

功能包括：

- 显示资料路径
- 一键复制路径
- 显示目录备注

例如：

- 客户档案路径
- 当前案件路径
- 主申请人资料路径
- 家属资料路径

先不做在线预览，不做上传，不做文件管理。

### 7. 客户跟进记录 / 备忘日志

这是客户中心的重要模块。

每次客户来访、沟通、提交材料、补件、电话联系、LINE 沟通，都要有日志记录，方便其他同事接手。

每条记录包含：

- 记录时间
- 记录人
- 记录类型
- 本次发生的事情
- 客户提交了什么
- 还缺什么
- 下次要做什么
- 下次跟进时间
- 内部备注

记录类型建议：

- 来访记录
- 电话沟通
- 微信 / LINE 沟通
- 材料提交
- 材料补交
- 内部备注
- 案件更新
- 续签提醒

### 8. 到期提醒与待办

客户中心里要有提醒能力。

提醒场景：

- 签证到期前两个月提醒
- 需要补件提醒
- 到了下次跟进时间提醒
- 今日待联系客户提醒

## 二、客户中心的页面结构

下面这部分最适合直接让 Stitch 出后台原型。

### 页面 1：客户列表页

#### 页面目标

让员工快速找到客户，并知道谁需要优先处理。

#### 页面内容

顶部：

- 搜索框
- 筛选器
- 新建客户按钮

筛选条件：

- 业务类型
- 当前状态
- 是否有家属
- 是否需要补件
- 是否即将到期
- 负责人

表格字段建议：

- 客户姓名
- 主申请人 / 家属标识
- 业务类型
- 当前状态
- 材料状态
- 签证到期日
- 下次跟进时间
- 负责人
- 操作按钮

右上角可有快捷卡片：

- 今日待跟进
- 即将到期
- 需要补件
- 最近新增客户

### 页面 2：新建客户 / 新建案件页

#### 页面目标

录入主申请人、业务类型、家属信息。

#### 页面结构

##### A. 主申请人信息区

- 姓名
- 性别
- 出生日期
- 国籍
- 联系方式
- 微信
- LINE
- 护照号（`docs/17` §1.12）
- 当前在留资格
- 签证到期日

##### B. 业务信息区

- 业务类型
- 当前状态
- 负责人
- 是否有家属成员
- 是否需要录入外部主申请人信息

##### C. 家族签特殊逻辑

如果业务是家族签，则显示：

关联方式：

- 本公司主申请人
- 外部主申请人

如果选“本公司主申请人”：

- 搜索并选择已有主申请人

如果选“外部主申请人”：

- 外部主申请人姓名
- 外部主申请人签证类型
- 外部主申请人签证到期日
- 与申请人关系
- 备注

##### D. 家属成员区

支持动态新增成员：

- 添加配偶
- 添加子女
- 继续新增

每个成员字段：

- 姓名
- 关系
- 性别
- 出生日期
- 国籍
- 护照号（`docs/17` §1.12）
- 当前状态

### 页面 3：客户详情页

#### 页面目标

一个页面看全客户、案件、家属、材料、日志、资料路径。

#### 页面布局建议

后台管理系统风格，左右分栏或上中下分区。

顶部信息卡：

- 客户姓名
- 客户编号
- 主业务类型
- 当前状态
- 签证到期日
- 负责人

快捷操作按钮：

- 编辑
- 新增跟进记录
- 新增提醒
- 复制资料路径

##### 模块 1：基本信息

- 基础资料
- 联系方式
- 护照信息（号码等主数据：`docs/17` §1.12）
- 在留资格信息

##### 模块 2：案件信息

- 业务类型
- 当前进度
- 补件情况
- 收费情况
- 到期时间
- 下次跟进时间

##### 模块 3：家属成员

用卡片或表格显示：

- 姓名
- 关系
- 业务类型
- 当前状态
- 材料状态

##### 模块 4：材料状态

用 checklist 展示：

- 护照已收 / 已扫描（材料状态；与主档护照号码见 `docs/17` §1.12）
- 在留卡已收 / 已扫描
- 住民票已提交
- 纳税资料已提交
- 其他材料状态
- 缺失材料说明

##### 模块 5：资料中心

显示本地服务器路径：

- 客户主档案路径
- 当前案件路径
- 主申请人资料路径
- 家属资料路径

操作：

- 复制路径
- 查看备注

##### 模块 6：跟进记录时间线

按时间倒序显示：

- 时间
- 记录人
- 类型
- 内容
- 下次动作
- 下次跟进日期

### 页面 4：新增跟进记录弹窗 / 页面

#### 字段

- 记录类型
- 记录时间
- 记录人
- 本次内容
- 客户提交了什么
- 还缺什么
- 下次要做什么
- 下次跟进时间
- 是否创建提醒

建议用表单 + 文本域，简单清楚。

### 页面 5：待跟进 / 提醒页

#### 页面目标

让员工每天先看这一页，就知道今天该联系谁。

分类卡片：

- 今日待跟进
- 7天内到期
- 2个月内到期
- 需要补件
- 已超过跟进日期

表格字段：

- 客户姓名
- 业务类型
- 提醒类型
- 到期日 / 跟进日
- 当前状态
- 负责人
- 快捷处理
