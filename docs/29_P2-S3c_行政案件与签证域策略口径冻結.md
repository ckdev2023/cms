# P2-S3c：`admin_cases` 与签证域关系策略（口径冻結）

> **文档定位**：计划 **P2-S3c** 产出。在 **不修改** `签证客户中心计划优化` 计划文件的前提下，在 **`docs/21`** 已冻结的职责边界内，明确 **行政案件域** 与 **签证域** 的长期关系：默认 **独立数据域 + 仅入口/导航合并**；**可选** **人工驱动的部分字段映射/补录** 至 `visa_cases`；**禁止** 与 `docs/21` 冲突的「统一主表迁移」或静默下线行政能力。  
> **上游**：职责边界与 API 保留见 `docs/21_签证客户中心P0验收与Rollout说明.md` §1、§3.2；字段级启发式对照与不可自动迁移项见 `docs/28_P2-S3a_旧提醒与行政案件向签证域差距评估.md` §2；旧入口弱化手段见 `docs/26_P1旧入口弱化策略口径冻結_P1-S5a.md`。

## 1. 与 `docs/21` 的对齐声明（硬约束）

以下条款与 `docs/21` **一致或为其子集**；若未来产品要求突破，须 **先修订 `docs/21`（及计划文件）** 再改实现。

| `docs/21` 既有冻结 | P2-S3c 遵守方式 |
|--------------------|-----------------|
| §1.1：`admin_cases` 为既有 **主对象**，与 `visa_cases` **并列域** | 维持 **两张主表、两套 API**（`/admin-cases/*` 与签证域接口并存） |
| §1.3：不做 **`admin_cases` 向签证域的统一迁移** | **不**将行政案件 **批量改写为** 唯一签证主档、**不**废弃 `admin_cases` 表或 `/admin-cases/*` |
| §3.2：行政案件 **全部接口保留不变** | 任何 P2-S3 导航或工作台 **不得** 以「合并」为名删除或 410 既有 REST 契约 |
| §14 / `docs/26`：弱化仅限排序、分组、折叠、文案 | 入口合并属 **弱耦合**；**不**用仅签证权限用户 **看不见** 行政深链来替代权限设计（行政仍依 `admin_case:*`） |

## 2. 策略选项的冻結结论

### 2.1 默认路径（冻結采用）：**独立域 + 仅入口合并**

| 要素 | 冻結口径 |
|------|----------|
| **数据** | `admin_cases` 与 `visa_cases` **不合并存储**；**不**引入「一案双写」同步中间表作为默认架构 |
| **行为** | 行政流水线（面谈、任务、行政文档子表）**全部**留在行政模块；签证流水线（家属、案件日志、`customer_file_paths`、签证提醒桶）**全部**留在签证模块 |
| **产品** | 侧栏、客户详情、工作台等 **导航层** 可将「行政案件」与「签证案件」 **同屏分组、并列链接、统一跳转出口**（承接 P2-S3e）；实现细节以 `docs/26` 允许手段为上限 |
| **验收** | 深链 `/admin-cases`、`/admin-cases/:id` 与 `docs/21` §14 书签表 **持续有效** |

### 2.2 可选路径（冻結允许范围）：**部分映射 = 人工补录签证案件，而非系统合并域**

「部分映射」**仅**指：在 **明确业务操作**（人工在 UI 勾选、或通过 **P2-S3d** 批处理工具在 dry-run 与幂等约束下）从 **一条** `admin_cases` **启发式生成或填充** **新的或已有的** `visa_cases` 部分字段。

| 允许 | 禁止 |
|------|------|
| 按 `docs/28` §2.2 对照，将 `customer_id`、`expire_date`、`owner_user_id`→`assigned_to` 等作为 **初始值** 写入签证案件（**须人工确认**） | **自动**认为「行政案件名 = 签证案件类型」或 **自动**对齐 `AdminCaseStatus` 与 `VisaCaseStatus` **无映射表** |
| 新建 `visa_cases` 后，行政侧记录 **仍可独立编辑**；两边 **允许长期并存** | 将 `admin_case_interviews` / `admin_case_tasks` / `admin_case_documents` **默认迁入** 签证域子模型 |
| 工具链复用 P1-S3 模式的 **dry-run、行级失败、审计**（见 `docs/28` §3 **P2-S3d**） | **静默**把行政案件标为「已迁移」并 **隐藏** 行政入口（违反 `docs/26`） |

### 2.3 明确不采纳（除非新开计划修订 `docs/21`）

| 方案 | 不采纳原因（摘要） |
|------|---------------------|
| **单域强统一**：废弃 `admin_cases` 或仅保留只读壳 | 与 `docs/21` §1.3、§3.2 **直接冲突** |
| **1:1 自动全量迁移** | `docs/28` §2.3：子表不对等、一案多申、枚举不兼容 |
| **双向实时同步** | 无冻结主数据归属规则，易产生漂移与审计纠纷 |
