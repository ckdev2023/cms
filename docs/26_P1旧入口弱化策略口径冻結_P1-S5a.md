# P1 旧入口弱化策略口径冻結（P1-S5a）

> **文档定位**：P1-S5（旧入口弱化）的 **S5a 冻結**。定义「主入口」范围、允许的弱化手段、**禁止事项**（含路由/API/权限不变原则），供 S5b–S5f 执行时对照，避免实施漂移。  
> **依赖**：建议在 P1-S4 主路径（全局案件列表、统计、客户派生风险）稳定后再动导航与文案层弱化（与计划文件 P1-S5 粒度说明一致）。

---

## 1. 目标

- 在 **不删除、不破坏** 既有能力与契约的前提下，通过 **信息架构与文案** 引导用户优先使用签证域主路径（新提醒、全局案件、客户详情签证 Tab）。
- 将「弱化」严格限定为 **可感知、可回退** 的调整：排序、分组、折叠、副标题/tooltip、空态提示层级等。
- **禁止**静默下线、**禁止**破坏深链书签、**禁止**擅自更名或删除权限码导致旧角色失权。

---

## 2. 「主入口」范围（冻結）

以下视为 **签证域主路径入口**（P1-S5 弱化策略的「优先侧」）：

| 范围 | 说明 |
|------|------|
| **侧栏/顶栏** | 签证相关菜单项：如 **签证提醒**（`/visa-reminders`）、**全局签证案件**（`/visa-cases`）等已落地路由；具体排序与分组由 S5b 实现，但须符合 §3–§4。 |
| **客户详情** | **签证域 Tab**（`CustomerVisaDomainTab` 及子区块）：案件、家属、资料路径、案件日志等与 `visa_cases` 直连的能力。 |
| **快捷跳转** | 从提醒列表、全局案件列表跳转到客户/案件详情等 **已存在** 的链接模式。 |

以下视为 **旧版/并存入口**（弱化对象，但必须 **保持可达**）：

| 范围 | 说明 |
|------|------|
| **旧在留提醒** | 路由 **`/customers/residence-reminders`**（或项目中等价路径）及接口 **`GET /customers/residence-expiry-reminders`**；口径仍基于 `person_info.residence_expire_date`，与 `docs/21` §6.4 一致。 |
| **行政案件** | `admin_cases` 域：列表、详情、客户详情内相关 Tab/区块；**不合并数据模型**（计划 P2-S3 再评估）。 |
| **其他既有客户中心 Tab** | 未列入签证主路径的 Tab（基本信息、附件 `files` 等）保持功能不变，仅可在 **排序/分组** 上与签证域区分优先级（S5c）。 |

---

## 3. 允许的弱化级别（冻結）

仅允许下列手段，且须 **用户仍能明确找到** 旧入口：

| 手段 | 示例 | 备注 |
|------|------|------|
| **排序** | 侧栏中将签证提醒、全局案件置于更靠前 | 不得从菜单中移除旧项 |
| **分组** | 「签证」「客户中心」「行政/旧版」等分组标题 | 分组名须在 i18n 中可读，避免贬损性用语 |
| **折叠** | 侧栏子菜单默认折叠旧分组 | 默认折叠时仍需 **一次点击内** 可展开到达旧页 |
| **文案层级** | 主路径用主标题；旧入口用副标题、说明「口径基于在留卡/行政案件」等 | 与 `docs/21` 兼容说明一致 |
| **空态与引导** | 在新提醒页空态提示「旧在留提醒仍可在 ○○ 菜单打开」 | 不得唯一链接失效 |

---

## 4. 禁止事项（冻結）

| 禁止项 | 说明 |
|--------|------|
| **删除或改名路由** | 旧在留提醒、行政案件、客户列表等 **既有 path/name** 不得删除；若需别名须在文档与迁移说明中单独立项（**不在 P1-S5 范围**）。 |
| **删除或废弃 API** | **`/customers/residence-expiry-reminders`** 及 `admin_cases`、`files`、客户备注等接口 **保持可用**；不可改为仅 410/404 且无替代说明。 |
| **静默下线** | 不得以「未挂菜单」「权限误改」等方式使旧能力仅对部分用户不可用；弱化仅限 §3 明示手段。 |
| **修改权限码语义** | 既有权限码（如 `customer:*`、`admin_case:*`）**不得**为弱化入口而改名或合并；签证子权限与旧权限 **独立**。 |
| **数据迁移伪装成 UI 弱化** | P1-S5 不包含将旧数据强制迁入 `visa_cases`；迁移属 P2-S3 或独立项目。 |

---

## 5. 深链与书签（冻結）

- 用户保存的 **完整 URL**（含 query）至旧在留提醒、行政案件、客户详情等页面，在弱化实施后须 **仍可访问**，且功能不因导航调整而缺失。
- 前端路由 `name`/`path` 变更若不可避免，须 **另起变更单**，**不属于** P1-S5a 收口范围；P1-S5 实施默认 **不改变** 既有 path。

---

## 6. 权限不变原则（冻結）

- **弱化为展示层与信息架构层**，**不**作为收紧或放宽权限的手段。
- 无 `visaReminder:list` 的用户：仍可通过既有权限访问旧在留提醒（若其角色原本具备客户列表/旧提醒相关权限）；详见计划 **P1-S5e** 边界。
- 新增菜单项仍按 `docs/21` §4 与既有 `permissions` 种子约定挂载，**不**因「主入口」叙事而绕过 Guard。
