# 事务所管理系统管理后台前端界面设计

## 1. 设计目标

管理后台前端应服务于事务所日常高频操作，重点满足以下目标：

- 快速搜索并进入客户详情
- 在一个后台中同时处理行政、税务、财务与内部事务
- 让高频列表、详情、审批、录入操作路径足够短
- 保证高风险动作可确认、可追踪、可回退

本系统是内部使用的小型后台，因此前端设计应优先考虑：

- 简单直接
- 页面清晰
- 员工容易上手
- 常用操作尽量少点几次

## 2. 适用角色

- 管理员
- 员工
- 财务人员
- 审批人员

界面展示需根据角色和权限动态控制菜单、按钮、字段与导出能力。

## 3. 后台信息架构

建议主导航结构如下：

1. 工作台
2. 客户中心
3. 行政书士
4. 税理士
5. 财务中心
6. 事务所管理
7. 文件中心
8. 日志审计
9. 系统设置

## 4. 全局布局设计

### 4.1 布局结构

- 左侧：主导航菜单
- 顶部：全局搜索、消息提醒、快捷新建、当前用户
- 中部：页面主体区域
- 右侧抽屉：客户快照、任务快照、审批快照（可选）

### 4.2 全局固定能力

- 顶部全局客户搜索
- 最近访问客户
- 待办任务角标
- 待审批角标
- 到期提醒角标

## 5. 页面清单设计

### 5.1 工作台

应包含：

- 今日待办
- 近期到期案件
- 本月申报期限
- 待处理请款 / 收款事项
- 待审批事项
- 最近访问客户

工作台不建议做得太复杂，重点是把“今天要做什么”展示清楚。

### 5.2 客户中心

页面建议：

- 客户列表页
- 新建客户页
- 客户详情页
- 客户关系/负责人页
- 客户备注与历史页

#### 客户列表页

字段建议：

- 客户编码
- 客户名称
- 类型（个人 / 法人）
- 服务类型
- 电话
- 负责人
- 最近跟进时间
- 状态

操作建议：

- 搜索
- 高级筛选
- 导出
- 新建客户
- 批量分配负责人

#### 客户详情页

建议采用“顶部摘要 + 标签页”模式：

- 顶部：客户基本信息卡片
- 标签页 1：基础信息
- 标签页 2：行政案件
- 标签页 3：税务业务
- 标签页 4：财务
- 标签页 5：任务与备忘
- 标签页 6：文件
- 标签页 7：日志

### 5.3 行政书士模块

页面建议：

- 行政案件列表
- 案件详情
- 面谈记录页
- 提交资料页
- 在留资格到期看板

列表筛选建议：

- 客户名称
- 案件状态
- 在留资格
- 到期时间区间
- 负责人

### 5.4 税理士模块

页面建议：

- 税务客户列表
- 顾问合同列表
- 月次资料列表
- 月次业务进度页
- 年末调整页
- 申报期限看板

月次页应突出：

- 所属期间
- 资料是否齐全
- 月次处理状态
- 申报截止日
- 风险提示

### 5.5 财务中心

页面建议：

- 请款列表
- 请款详情
- 收款登记页
- 预收款台账
- 客户财务总览页
- 财务对账页

关键交互要求：

- 新建收款时必须显示对应请款余额
- 预收款抵扣时显示抵扣前后余额
- 金额修改需二次确认并提示是否走审批

### 5.6 事务所管理

页面建议：

- 任务中心
- 内部申请单列表
- 审批中心
- 用户管理
- 角色权限管理

审批中心需支持：

- 待审批
- 已审批
- 我发起的
- 已驳回

### 5.7 文件中心

页面建议：

- 客户文件树
- 行政资料目录
- 税务资料目录
- 财务附件目录
- 文件访问记录

文件页关键能力：

- 按客户快速定位
- 按模块分类过滤
- 显示文件路径、上传人、更新时间、访问记录

### 5.8 日志审计

页面建议：

- 登录日志
- 操作日志
- 删除日志
- 导出日志
- 审批日志

## 6. 关键交互规范

### 6.1 表格页规范

- 默认使用分页表格
- 支持列筛选、排序、固定操作列
- 高风险按钮如删除、作废、审批通过使用二次确认
- 常用操作尽量放在列表页直接完成，减少来回跳转

### 6.2 表单页规范

- 长表单分区展示
- 必填项突出显示
- 保存与提交分离
- 敏感字段修改显示风险提示
- 能拆成短表单的不要强行做成长表单

### 6.3 详情页规范

- 统一采用“摘要卡 + 标签页 + 右侧操作区”
- 核心状态信息必须置顶
- 最近日志与最近任务可快速预览
- 优先保证信息一眼能看懂，而不是追求复杂布局

## 7. 视觉与状态规范

建议统一状态色：

- 成功 / 完成：绿色
- 进行中：蓝色
- 待处理：橙色
- 风险 / 临期：红色
- 已作废 / 已停用：灰色

建议统一标签：

- 客户类型标签
- 服务类型标签
- 状态标签
- 风险等级标签

## 8. 权限驱动的前端设计要求

前端需支持以下权限控制粒度：

- 菜单是否显示
- 页面是否可进入
- 按钮是否可点击
- 字段是否可见
- 金额是否脱敏
- 导出是否可用

对于本项目，一期不建议做过细权限，通常控制到“菜单 + 页面 + 关键按钮”即可。

注意：前端权限仅用于交互控制，最终权限以服务端校验为准。

## 9. 建议的前端组件体系

建议沉淀以下公共组件：

- 客户选择器
- 客户摘要卡
- 状态标签组件
- 权限按钮组件
- 审批流组件
- 金额摘要组件
- 文件列表组件
- 日志时间轴组件
- 高级筛选栏组件

## 10. MVP 页面优先级

### 优先级 P0

- 登录页
- 工作台
- 客户列表 / 详情
- 行政案件列表 / 详情
- 税务合同 / 月次列表
- 请款列表 / 收款登记
- 用户与角色管理

### 优先级 P1

- 预收款台账
- 简单审批
- 文件中心
- 日志中心

### 优先级 P2

- 报表页
- 提醒中心
- Google 日历联动页

## 11. 前端技术建议

推荐：

- Vue 3
- TypeScript
- Vite
- Element Plus
- Pinia
- Vue Router
- Axios 或同类请求库

该组合更适合内部管理后台的表单、表格、弹窗、抽屉、上传、筛选等常见场景，开发效率高，也更容易让小团队快速接手。

如果团队已经非常熟悉 React，也可以继续使用 React；但如果目标是“简单、快、易维护”，则本项目更推荐 Vue 3。

## 12. 用户体验重点与对应技能

本项目的用户体验重点不是炫酷，而是：

- 少点几次
- 更快找到客户和案件
- 表单更少出错
- 文件更容易上传、找到和预览
- 财务录入更不容易重复和误操作

建议重点具备以下技能：

- 信息架构设计：菜单、页面分组、详情页信息聚合
- 表单体验设计：字段分组、默认值、校验提示、保存反馈
- 表格体验设计：搜索、筛选、排序、批量操作、快捷入口
- 状态反馈设计：加载、空状态、错误提示、成功提示
- 国际化基础：日文文案、日期格式、金额格式、全角/半角兼容

## 13. 文件与 Office 处理能力建议

一期建议先做“够用”的文件能力：

- 文件上传
- 文件下载
- 图片预览
- PDF 预览
- 文件元数据编辑
- 文件与客户 / 案件 / 税务 / 财务记录关联
- 文件权限与操作日志

Excel 建议：

- 先做导出
- 再做模板导入
- 导入前先校验并返回错误行
- 一期不做复杂在线 Excel 编辑

DOCX 建议：

- 先做上传、下载、归档
- 如有模板文书，再补 DOCX 模板生成
- 预览优先采用“转 PDF 后预览”
- 一期不做复杂在线 DOCX 编辑

推荐沉淀的公共组件还应包含：

- 文件上传组件
- 文件预览抽屉
- Excel 导入结果反馈组件
- 下载按钮与权限控制组件
- 操作确认弹窗组件
