# 事务所管理系统详细开发执行步骤

## 1. 文档目标

本文用于把现有规划文档进一步拆成可执行步骤，方便按顺序推进开发。

适用方式：

- 按步骤顺序执行
- 每完成一步再进入下一步
- 每一步先看前置条件、再做操作、最后核对完成标准

## 2. 执行原则

本项目是内部小型 CMS，执行时遵循以下原则：

1. 先做主流程，再补细节
2. 先做高频功能，再做增强能力
3. 先保证可用，再追求完整
4. 尽量复用通用组件和通用表结构
5. 一期默认以 PostgreSQL 为主路线，Access 仅作为备选方案

## 3. 开发前必须先确认的事项

在正式开发前，先确认以下 6 项：

1. 一期模块范围是否只做客户、业务、财务、文件、工作台
2. 主数据库是否确定为 PostgreSQL
3. 文件是上传到系统还是仅记录共享目录路径
4. 角色是否采用管理员、业务员工、财务人员三类为主
5. 财务是否需要简单审批进入一期
6. 部署环境是单机、云服务器还是公司内部服务器

## 4. 主执行路线总览

建议按以下顺序推进：

1.  冻结范围与角色
2.  确认技术栈与数据库
3.  初始化前后端项目
4.  建立数据库主表与枚举
5.  完成登录与用户角色
6.  搭建后台布局与菜单
7.  开发客户中心
8.  开发行政书士事务模块
9.  开发税理士模块
10. 开发财务模块
11. 开发文件模块
12. 开发工作台与提醒
13. 接入权限、日志、删除保护
14. 联调、初始化数据与试运行
15. 部署、备份与上线准备

## 5. 详细执行步骤

### 5.1 步骤 01：冻结一期范围与业务边界

目标：确认系统一期到底做哪些模块，避免开发中途反复改方向。

前置条件：已有需求文档和开发文档可参考。

具体操作：

- 确认 P0 只保留高频模块
- 确认哪些功能延后到 P1/P2
- 确认角色只做基础 RBAC，不做复杂数据隔离
- 确认关键状态枚举和业务口径

对应技能：

- 需求分析
- 业务梳理
- 系统边界控制

产出物：

- MVP 功能清单
- 一期不做清单
- 角色范围确认表

完成标准：团队对“一期做什么、不做什么”达成一致。

### 5.2 步骤 02：确认技术栈与数据库方案

目标：固定技术路线，避免后续重复重构。

前置条件：步骤 01 已完成。

具体操作：

- 确认前端使用 Vue 3 + TypeScript + Element Plus
- 确认后端使用 NestJS + Node.js
- 确认数据库优先使用 PostgreSQL
- 确认文件存储为 NAS、共享目录或本地目录
- 如果客户坚持 Access，明确只作为备选或过渡方案

对应技能：

- 技术选型判断
- 后端框架认知
- 数据库基础
- 部署基础认知

产出物：

- 最终技术栈确认表
- 数据库选型结论
- 文件存储方案说明

完成标准：技术路线固定，后续开发不再临时换栈。

### 5.3 步骤 03：初始化项目骨架与代码仓库

目标：建立可运行的前后端基础工程。

前置条件：步骤 02 已完成。

具体操作：

- 初始化前端项目和后台基础布局
- 初始化 NestJS 后端项目
- 配置环境变量、接口前缀、跨域和日志中间件
- 建立 Git 分支规范、worktree 使用方式和基础目录结构
- 配置前后端基础单元测试框架
- 配置开发、测试、生产环境参数模板

对应技能：

- Node.js 与包管理
- Vue 3 工程初始化
- NestJS 项目初始化
- Git 基础
- Git worktree 基础
- 环境配置管理

产出物：

- 可启动前端项目
- 可启动后端项目
- `.env` 模板和 README

完成标准：前后端都能本地启动，仓库结构稳定。

### 5.4 步骤 04：建立数据库主表、字典与枚举

目标：先把主流程依赖的数据结构搭好。

前置条件：步骤 03 已完成。

具体操作：

- 建立用户、角色、权限表
- 建立客户、跟进记录表
- 建立行政案件、税务合同、税务月次表
- 建立请款、收款、预收款表
- 建立文件表、操作日志表
- 建立通用状态枚举和字典表

对应技能：

- SQL
- 数据库建模
- 主外键设计
- 索引设计
- 迁移脚本管理

产出物：

- 数据库建表脚本
- 初始化字典数据
- 数据库版本说明

完成标准：主表可创建成功，核心关系能支撑后续接口开发。

### 5.5 步骤 05：完成登录、用户与角色基础能力

目标：让系统先具备“谁能登录、谁能看到什么”的基础能力。

前置条件：步骤 04 已完成。

具体操作：

- 实现登录、退出、修改密码接口
- 建立用户列表、新建用户、启停用用户功能
- 完成角色绑定和权限编码返回
- 前端接入登录态存储和路由守卫

对应技能：

- JWT 或 Session 鉴权
- 密码加密
- RBAC 基础
- 前端登录态管理

产出物：

- 登录页
- 用户管理页
- 登录相关 API

完成标准：管理员可登录，普通用户可登录，停用账号无法登录。

### 5.6 步骤 06：搭建后台基础布局、菜单与公共组件

目标：统一后台壳子，避免后面每个页面重复搭建。

前置条件：步骤 05 已完成。

具体操作：

- 搭建侧边菜单、顶部栏、面包屑和标签页结构
- 建立通用表格、筛选区、表单弹窗、详情抽屉组件
- 统一列表页、详情页、编辑页的页面模板
- 建立通用请求封装和错误提示处理

对应技能：

- Vue 3 组件设计
- Element Plus 布局与表单
- 路由管理
- 前端公共组件抽象

产出物：

- 后台主布局
- 公共表格和表单组件
- 页面模板

完成标准：后续模块页面都可以基于统一模板快速开发。

### 5.7 步骤 07：开发客户中心

目标：先完成系统主入口，所有业务都围绕客户展开。

前置条件：步骤 06 已完成。

- 开发客户跟进记录功能

对应技能：

- 聚合查询

产出物：

- 客户中心页面
- 客户接口
- 客户详情聚合接口

完成标准：员工可以完整管理客户主档并查看客户总览。

### 5.8 步骤 08：开发行政书士事务模块

目标：完成行政案件的录入、查询和跟进。

## 7. PostgreSQL 主路线与 Access 备选说明

### 7.1 推荐主路线

正式系统建议以 PostgreSQL 为主数据库，原因是：

- 更适合多人并发
- 更适合 Web 管理系统
- 更适合财务和日志类数据
- 更方便后续扩展和部署

### 7.2 如果客户坚持 Access

建议采用以下限制策略：

- Access 仅用于早期原型或历史数据导入
- 正式系统后端尽量保留迁移到 PostgreSQL 的能力
- 避免复杂并发写入场景
- 财务和日志能力尽量不要过度依赖 Access 特性

## 8. 使用建议

建议实际执行时采用以下节奏：

1. 每完成 1 个步骤就更新一次执行记录
2. 每完成 1 个主模块就做一次内部演示
3. 公共骨架稳定后，可按模块拆分分支并通过不同 worktree 并行开发
4. 并行开发时优先按模块分工，避免多人同时改同一批公共文件
5. 每个分支至少完成本模块单元测试后再合并到 release
6. 发现业务口径不清时先确认，再开发

一句话总结：**先按顺序做出可用版本，再基于真实使用情况逐步优化。**
