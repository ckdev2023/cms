# 事务所管理系统 MVP 开发排期与WBS

## 1. 文档目标

本文用于明确本系统 MVP 版本的开发范围、阶段计划和任务拆分，帮助项目尽快进入可执行状态。

本项目定位为内部小型 CMS，因此目标不是一次做全，而是：

- 先做高频功能
- 先做员工每天都会用的功能
- 先上线一个可用版本

## 2. MVP 目标

MVP 版本建议先满足以下目标：

1. 员工可以登录系统
2. 可以管理客户资料
3. 可以处理行政案件和税务月次
4. 可以登记请款、收款和预收款
5. 可以上传和查看文件
6. 可以通过工作台看到待办和到期事项

## 3. MVP 范围

### 3.1 P0 必做范围

- 登录
- 用户管理
- 客户管理
- 行政书士事务模块基础版
- 税理士模块基础版
- 财务模块基础版
- 文件上传与归档
- 工作台基础版

### 3.2 P1 建议后续补充

- 简单审批
- 导出功能
- 日志查看页面
- 统计报表

### 3.3 P2 后续增强

- 更复杂提醒规则
- 更细权限模型
- BI 看板
- 外部系统集成

## 4. 建议开发周期

如果团队配置较精简，建议以 **6~8 周** 为一个 MVP 周期。

推荐节奏：

- 第 1 周：需求冻结 + 技术搭建
- 第 2~3 周：客户、行政、税务
- 第 4~5 周：财务、文件、工作台
- 第 6 周：权限、日志、联调、修复
- 如条件允许，第 7~8 周：试运行与优化

## 5. WBS 任务拆分

### 5.1 阶段一：项目启动与基线确认

目标：把“做什么”和“怎么做”确认清楚。

任务：

1. 确认 MVP 范围
2. 确认角色与权限边界
3. 确认核心状态枚举
4. 确认数据库主表结构
5. 确认页面清单和菜单结构
6. 确认文件存储方式

交付物：

- 需求基线
- 架构文档
- 数据库设计
- API 设计
- 权限矩阵

### 5.2 阶段二：基础框架搭建

目标：完成项目可开发基础。

任务：

1. 初始化前端项目
2. 初始化后端项目
3. 建立数据库连接与基础表
4. 完成登录鉴权
5. 完成菜单、路由、基础布局
6. 建立公共组件和公共返回结构

交付物：

- 可运行前端骨架
- 可运行后端骨架
- 登录页
- 基础布局页

### 5.3 阶段三：核心业务模块开发

目标：完成最核心的业务录入和查询能力。

任务：

1. 客户列表、详情、新建、编辑
2. 行政案件列表、详情、新建、编辑
3. 税务合同和月次列表、详情、编辑
4. 客户跟进记录
5. 关联搜索和基础筛选

交付物：

- 客户中心可用
- 行政书士事务模块可用
- 税理士模块可用

### 5.4 阶段四：财务与文件模块开发

目标：补齐日常工作闭环。

任务：

1. 请款单管理
2. 收款登记
3. 预收款台账和流水
4. 文件上传、列表、删除、下载
5. 客户详情中的财务摘要和文件摘要

交付物：

- 财务中心基础可用
- 文件中心基础可用

### 5.5 阶段五：工作台、权限与日志

目标：提升日常使用效率，并补足基础控制。

任务：

1. 工作台汇总卡片
2. 待办与到期提醒
3. 角色权限接入
4. 操作日志记录
5. 删除确认和基础风险控制

交付物：

- 工作台可用
- 基础权限可用
- 基础日志可用

### 5.6 阶段六：联调、测试与上线准备

目标：完成可上线版本。

任务：

1. 前后端联调
2. 关键流程测试
3. 修复主要问题
4. 配置数据库备份
5. 配置文件备份
6. 准备初始化数据和账号

交付物：

- MVP 发布版本
- 上线检查清单

## 6. 建议的人员分工

精简团队建议如下：

- 产品/需求确认：1 人
- 前端开发：1 人
- 后端开发：1~2 人
- 测试/实施：1 人（可兼职）

如果人更少，也可以采用全栈方式推进。

## 7. 关键里程碑

### M1：需求与设计冻结

- 模块范围确定
- 表结构确定
- API 基线确定

### M2：主模块完成

- 客户、行政、税务完成基础功能

### M3：闭环完成

- 财务、文件、工作台完成

### M4：上线准备完成

- 权限、日志、备份、联调完成

## 8. MVP 验收标准建议

上线前建议至少满足：

1. 登录正常，账号可停用
2. 客户增删改查正常
3. 行政案件和税务月次可录入和查询
4. 请款、收款、预收款可正常登记
5. 文件可上传、查看、删除
6. 工作台能看到待办和到期事项
7. 管理员和普通角色权限有区别
8. 关键操作有基础日志
9. 数据库和文件已配置备份

## 9. 当前最需要尽快确认的事项

为了避免开发反复，建议优先确认：

1. 客户和业务状态枚举
2. 财务登记规则和作废规则
3. 文件到底是只存路径还是支持上传
4. 是否需要简单审批进入一期
5. 哪些角色需要看到财务页面

## 10. 架构师建议

这个项目最适合的推进方式不是“大而全排期”，而是：

1. 先做主流程
2. 先让员工用起来
3. 再根据实际反馈优化页面和细节

一句话总结：**MVP 先交付可用性，再逐步补完整性。**
