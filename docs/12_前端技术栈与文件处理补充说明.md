# 前端技术栈与文件处理补充说明

## 1. 文档目标

本文件用于补充说明前端技术栈、管理后台 UI 框架、用户体验重点，以及 Excel / DOCX / 文件上传下载预览编辑的实施建议。

## 2. 前端推荐结论

建议采用以下组合：

- Vue 3
- TypeScript
- Vite
- Element Plus
- Pinia
- Vue Router
- Axios 或同类请求库

该组合更适合内部管理后台的快速开发、持续维护和小团队协作。

## 3. 为什么本项目优先 Vue 3

主要原因如下：

1. 模板写法更直观，适合表单和表格类页面
2. 后台常见场景资料多，开发上手更快
3. 对单人或小团队开发更友好
4. 与 Element Plus 组合时，后台页面搭建速度更高

如果团队已经非常熟悉 React，也可以继续使用 React；但本项目默认优先 Vue 3。

## 4. 管理后台 UI 框架建议

### 4.1 首选：Element Plus

推荐原因：

- 表单、表格、弹窗、抽屉、上传组件成熟
- 中文文档和示例丰富
- 适合内部后台系统
- 开发成本较低

### 4.2 备选：Naive UI / Arco Design Vue

可作为备选，但从“稳、快、通用”角度，仍优先 Element Plus。

## 5. 用户体验重点与技能

本项目的用户体验重点是效率，不是炫技。

建议重点具备以下技能：

- 信息架构：菜单、页面分组、详情页信息组织
- 表单设计：字段分组、默认值、错误提示、保存反馈
- 表格设计：搜索、筛选、排序、快捷操作、批量操作
- 状态反馈：加载、空状态、错误提示、成功提示
- 国际化基础：日文文案、日期格式、金额格式、全角/半角兼容

## 6. 文件能力建议按阶段建设

### 6.1 P0 一期必须做

- 文件上传
- 文件下载
- 图片预览
- PDF 预览
- 文件元数据编辑
- 文件与客户 / 案件 / 税务 / 财务记录关联
- 文件权限校验和操作日志

### 6.2 P1 二期建议补充

- Excel 模板导入
- Excel 导出
- DOCX 模板生成
- 文件版本管理
- 导入结果反馈和错误行导出

### 6.3 P2 三期再考虑

- 在线 Office 编辑
- 协同编辑
- OCR、电子签章、复杂文档流转

## 7. Excel 处理建议

推荐策略：

- 小数据量导出可同步生成
- 大数据量导出可异步生成
- 导入必须先模板化，再做字段和行级校验
- 导入前先预览结果，再确认写入

建议优先级：先导出，再导入，最后再考虑复杂在线编辑。

## 8. DOCX 处理建议

推荐策略：

- 一期先做上传、下载、归档
- 如有标准文书，再补 DOCX 模板生成
- 浏览器预览优先采用“转 PDF 后预览”
- 一期不做复杂在线 DOCX 编辑

原因是在线 Office 编辑集成成本高、维护复杂，不适合当前 MVP 阶段。

## 9. 上传、下载、预览、编辑的边界建议

建议这样控制范围：

- 上传：类型、大小、归属对象、上传人、时间都要记录
- 下载：必须做权限校验和下载日志
- 预览：先支持图片和 PDF，Excel / DOCX 以简单预览或转换预览为主
- 编辑：一期只编辑文件元数据，不做原文件在线编辑

## 10. 相关技能清单

前端需要：

- Vue 3 组件开发
- Element Plus 表单 / 表格 / 上传组件
- 文件下载和 Blob 处理
- 预览抽屉或预览页设计

后端需要：

- NestJS 文件上传下载
- 文件流处理
- Excel 导入导出
- DOCX 模板生成或 PDF 转换
- 文件权限与日志记录

一句话总结：**前端选 Vue 3 + Element Plus，文件能力先做上传、下载、预览、归档，不急着做复杂在线编辑。**
