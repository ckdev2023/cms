# 事务所管理系统总体架构与实施规划

## 1. 文档目标

本文用于明确本系统应采用什么样的实现方式，确保后续开发方向一致。

本项目不是大型企业平台，而是一个：

- 公司内部使用的业务管理系统
- 用户数量有限
- 业务流程相对固定
- 目标是提升员工日常处理客户、案件、税务、财务和文件的效率

因此架构上应坚持：**够用、简单、稳定、便于迭代**。

## 2. 架构结论

建议本项目采用以下方案：

- **产品形态**：内部 Web 管理后台
- **架构模式**：单体应用
- **前后端模式**：前后端分离，或一体化部署均可
- **数据库**：PostgreSQL
- **文件存储**：NAS 或公司内部共享目录
- **安全策略**：基础账号权限 + 操作日志 + 数据备份

不建议做复杂设计，例如：

- 不做微服务
- 不做复杂工作流引擎
- 不做过细的数据权限模型
- 不做重型安全体系

## 3. 系统定位

这个系统本质上是一个“内部业务效率工具”，重点解决：

1. 客户资料分散
2. 案件和税务进度不好追踪
3. 财务登记和对照不方便
4. 文件归档难找
5. 员工待办和到期事项容易遗漏

因此系统设计应以“员工每天愿意用、能快速用”为第一目标。

## 4. 核心模块

建议一期只保留以下主模块：

| 模块     | 主要用途                             |
| -------- | ------------------------------------ |
| 工作台   | 查看待办、即将到期事项、最近处理客户 |
| 客户中心 | 客户建档、搜索、查看完整资料         |
| 行政书士事务 | 行政案件录入、跟进、到期提醒         |
| 税理士   | 合同、月次资料、申报进度管理         |
| 财务中心 | 请款、收款、预收款和简单对账         |
| 文件中心 | 客户资料、案件资料、财务附件归档     |
| 系统设置 | 用户、角色、基础字典配置             |

## 5. 页面与操作原则

系统页面设计建议遵循以下原则：

### 5.1 操作路径短

- 找客户要快
- 登记事项要快
- 查看财务要快
- 上传文件要快

### 5.2 客户作为主入口

- 客户详情页应汇总客户、案件、税务、财务、文件、跟进记录
- 员工尽量从客户页进入各类业务操作

### 5.3 列表优先

- 以表格列表 + 筛选 + 搜索为主
- 少做复杂跳转
- 少做过深的多层菜单

## 6. 推荐技术架构

### 6.1 应用结构

建议采用简单分层：

1. 前端页面层
2. API 接口层
3. 业务服务层
4. 数据访问层
5. PostgreSQL + 文件目录

### 6.2 模块拆分建议

- `auth`：登录和用户信息
- `customer`：客户管理
- `admin-case`：行政案件
- `tax`：税务业务
- `finance`：请款和收款
- `file`：文件元数据和上传下载
- `system`：用户、角色、字典
- `log`：操作日志

这里的模块是代码组织方式，不代表要拆成独立服务。

## 7. 部署建议

### 7.1 推荐方式

对于内部系统，建议优先采用简单部署：

- 1 台应用服务器
- 1 个 PostgreSQL 数据库
- 1 个 NAS 或共享文件目录

如果系统体量更小，也可以：

- 前后端部署在同一台服务器
- 数据库单独部署

### 7.2 环境建议

- 开发环境
- 测试环境
- 生产环境

一般不必一开始就做预生产环境，除非公司流程要求。

## 8. 一期范围建议

### 8.1 P0 必做

- 登录
- 客户管理
- 行政案件管理
- 税务业务管理
- 财务登记
- 文件上传与归档
- 工作台提醒
- 用户和角色管理

### 8.2 P1 建议后续补充

- 操作日志查看
- 导出功能
- 简单审批
- 统计报表

### 8.3 P2 可选增强

- 更细的提醒规则
- 日历集成
- 更复杂报表
- BI 看板

## 9. 非功能要求

不追求“大型系统级别”的非功能设计，但以下内容建议保留：

### 9.1 性能

- 常用列表支持分页
- 首页和客户详情避免一次性加载全部内容
- 常用查询字段加索引

### 9.2 稳定性

- 关键写入操作使用事务
- 删除要二次确认
- 财务登记要避免重复提交

### 9.3 可维护性

- 代码按模块组织
- 接口命名统一
- 表结构命名统一
- 操作日志留痕

## 10. 开发实施建议

### 阶段 1：先做能用

- 完成登录
- 完成客户中心
- 完成行政、税务、财务基础录入
- 完成文件上传和查询

### 阶段 2：再做顺手

- 增加工作台
- 增加筛选、排序、快捷操作
- 增加导出和简单统计

### 阶段 3：最后做增强

- 补日志查看
- 补审批
- 补提醒规则优化

## 11. 架构师最终建议

本项目不适合按“大而全企业平台”建设，最佳方式是：

1. 先做一个轻量、稳定、员工愿意用的内部系统
2. 先解决客户、案件、税务、财务、文件这些高频问题
3. 等员工真正用起来后，再按反馈补功能

一句话总结：**先做实用工具，再慢慢长成功能系统。**
